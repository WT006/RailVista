### P0-1 · 拓扑重建：让本地 A* 真正可用（最高优先）

**现状（实测）**：`data/roads/china-road-topo.meta.json` 仍是旧产物 ——
`nodeCount 182,007 / edgeCount 206,609 / roadKeys 33 / mainCompNodes 31,300（17%） / generatedAt 2026-10-01`。
它由旧的 33 条几何构建，且用「坐标量化 1e-5 + 1km 跨线边」近似连图：
- 坐标量化把同一物理节点拆成多个 → 图碎裂；
- 1km 跨线边又把不相关的路强行连上 → 假连通。
结果：`/api/drive/route?engine=local` 仍然大范围降级为两点直线。

**怎么做**（方案 §五 P5）：
1. 节点改用 **OSM node id**（u64，跨省天然唯一），共享节点自动合并，不需要任何容差参数；
2. 两级图：
   - `trunk.rvrt`：E+G+S 全国一张（源码 `data/roads/net/*.rvwn` 里按等级筛）；
   - `{prov}.rvrt`：省片全域图（含 X/Y/C/unclassified），省界 20km 缓冲带两片都存，跨省按 node id 拼接；
3. **删掉 1km 跨线边启发式**（在 trunk 图里，路口在 OSM 中本就是共享节点）；
4. `edgeLine` 语义扩展：现在是 u16 的 roadKey id（上限 65535），15,230 条编号公路够用，但省片图要装 794 万条 way 时需改成 `edgeWay`（u32）+ 单独的 way→key 映射表。

**文件**：`scripts/build-road-topology.mjs`（重写）、`apps/api/src/services/roadTopology.ts`（省片加载 + snap 策略）、
`packages/shared/src/types.ts`（`RoadTopoMeta` 增 `prov`/`trunk` 字段）。

**验收**：
~~~bash
node scripts/build-road-topology.mjs --all
#  [trunk] 节点 3,500,000±  边 4,500,000±  连通分量 1  主分量 100.0%  → trunk.rvrt ~120MB
#  [prov ] zhejiang 节点 3,120,441 边 3,988,020 分量 1 → topo/zhejiang.rvrt 41MB
node scripts/eval-od.mjs --sample 1000       # 需新建（方案 §五 P7）
#  省内 600 组：成功 600（100.0%）
#  跨省 400 组：成功 ≥380（≥95%）  平均耗时 <400ms
#  RESULT PASS
curl -s "localhost:3000/api/drive/route?from=上海&to=拉萨&engine=local" | head -c 200
#  {"ok":true,"data":{"route":{...,"engine":"local",...}}}   ← 不允许再出现 "direct"
~~~

**注意**：trunk 图若超过 API 常驻内存预算（当前 RVRT 全量读入内存），
要么把 S 从 trunk 挪到省片，要么把 CSR 改成 mmap 分段读（`loadRoadTopology` 里已是一次性读入）。

### P1-1 · 长断口补全：让长线真正连成一条

**现状（全部 15,117 条编号公路）**：

~~~
连通分量：中位 1 · p75 3 · p90 6 · p99 23 · 最大 301；单分量 7,834 条（52%）；>50 分量 78 条
断口：33,180 处 · 中位 8.13km · p90 187km · 最大 2,061km
      <0.5km 7,420 · 0.5~5km 7,020 · >5km 18,740
已缝合：27,958 处（≤1.5km 紧公差，只影响绘制不影响里程）
~~~

**根因**：OSM 里长线穿城时 ref 断掉，且断口常常是**无 ref 的普通路段**。
现有算法只在**同一编号**的分量之间按几何距离缝合（≤1.5km），拿不到跨 ref 的接续段。

**怎么做**：给 `assembleComponents` 增加"跨 ref 接续"：
1. 建**省片级节点→way 索引**（`节点 id → way 序号` 的有序数组 + 二分；794 万 way 约 1,580 万端点，
   用 `Float64Array` 排序数组，内存约 250MB/省，可接受）；
2. 对每个断口两端点，在索引里做**有界 BFS**（深度 ≤6 段、总长 ≤5km、只走 trunk/primary 等级）；
3. 找到的通路作为 `bridged` 段并入几何（`RoadGeometry.bridgedSegments`），
   **不计入 `totalKm`**（里程口径不变），UI 用实线+浅色区分；
4. 找不到就保留断口（诚实优先）。

**验收**：
~~~bash
node scripts/build-road-geom.mjs --key G318 && node -e "const g=require('./data/roads/geom/G318.json');console.log(g.componentCount, g.stitchedGaps, g.bridgedGaps, g.totalKm)"
#  预期：分量 114 → ≤40；bridgedGaps > 0；totalKm 5346.6 不变（±0.5%）
node scripts/verify-road-network.mjs     # 仍 RESULT PASS
~~~

## 四、环境与踩坑备忘（血泪，务必继承）

1. **PBF 源**：`download.openstreetmap.fr/extracts/asia/china/{prov}-latest.osm.pbf` 实测可达（31 省 1.72GiB / 2.34MB/s）；
   `download.geofabrik.de` 与 `planet.openstreetmap.org` 在本机网络**不通**。备源 `ftpmirror.your.org`。
2. **沙箱 EPERM**：本机 DSH 沙箱下 `vite` / `tsx` 的 dev server（esbuild 用管道 stdio spawn 服务）报 `spawn EPERM`。
   - 构建：`pnpm --filter @railvista/api build`（tsc）可直接跑；`pnpm --filter @railvista/web build`（vite）需放宽权限执行一次；
   - 探针：`node scripts/drive-probe.mjs`（无头 Edge）同样需放宽权限；
   - **不要**为了绕过而改架构。
3. **PowerShell**：`pnpm`/`npm` 必须用 `pnpm.cmd`；不支持 heredoc；行内 `node -e` 的引号会被改写 ——
   **复杂命令一律写临时 `.mjs` 再 `node` 执行**。
4. **文件名坑（曾把全部省道几何写丢）**：不要用 `key.replace(/[^\w:]/g,'_')`：
   中文省名会被替换成 `_`，而 `':'` 在 Windows 上是 **NTFS 备用数据流**语法 ——
   `青海:S101` 会写进名为 `__` 的 ADS 流。**统一用 `road-ref.mjs` 的 `keyToFileName()`**（只替换 `:/\*?"<>|`），
   API 侧（`roadNetwork.ts`）与 `verify-road-network.mjs` 必须保持同一规则。
5. **编号坑**：`G0111` 是**国家高速联络线**，不是国道 G111。`canonicalRef()` 已按"G+4 位保持原样、其余去零填充"处理，
   **不要**再写"一律去零填充"。
6. **省外节点坑**：省级裁剪会把跨省 way 的省外节点裁掉。必须写 **NaN**，不能留 `0` ——
   曾因此把 `(0,0)` 当成真实坐标，单条 way 算出 45 万 km，全省里程虚高百倍。
7. **求值顺序坑**：`this.p += f()` 会先读旧值再调用 f，osm-pbf 的 `skip()` 已按 `const n = f(); this.p += n` 修正。
8. **大文件策略**：`data/cache/`、`data/roads/net/`、`data/roads/geom/` 全部 gitignore（可由 PBF 重建）；
   **新克隆仓库必须先跑 `pnpm roads:fetch → roads:ways → roads:geom → roads:index`**，否则 API 只有索引没有几何。
9. **并行任务**：工作区里有**另一路未提交的 UI 改动**（`App.vue`/`AppTopBar.vue`/`SelectTrip.vue`/`base.css`/`drive.css` 等）。
   提交时**必须显式列路径**，严禁 `git add -A`。
10. **测试基线**：`pnpm --filter @railvista/shared test` 与 api 的既有测试与路网无关；
    路网自身的验证靠 `selftest-assemble.mjs` + `verify-road-network.mjs` + API 探针三件套。
