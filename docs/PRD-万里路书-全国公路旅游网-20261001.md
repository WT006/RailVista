## 〇、一页纸：这一版改了什么

### 0.1 v1 的错误（需求方明确指出，必须先认账）

| # | v1 的做法 | 为什么错 | v2 的纠正 |
|---|---|---|---|
| 1 | 把「12 条国家级精品线」当成自驾模块的**主体**，先造 G315 一条线，全国靠后 | 用户要的是**和铁路一样**：全国覆盖 + 搜索 + 任意路线都能看景点。12 条线只是国家部委的一份**名单**，不是产品骨架 | 主功能改成「全国公路旅游网」；12 条线降为**排行榜榜单之一** |
| 2 | 只做了「一条预置路线的景点」 | 用户说："无论我走在哪条国道上，或者我从哪个位置到哪个位置，我只要走过，都可以把它的景点加载出来" | 核心能力重做成 **OD 任意点对点 → 出路线 → 出沿程景点**，且支持「选一条国道整条」和「实时我在哪」三种入口 |
| 3 | 排行榜完全没做 | 用户列举的三类榜单（国家精品自驾旅游公路实施方案 / 中国国家地理最美公路 / 其他最美自驾路线）一个都没有 | 新增 §7 统一榜单模型，三类榜单 + 各省榜一次性纳入，榜单是**路网之上的过滤器**，不是平行世界 |
| 4 | 没有搜索能力 | 铁路有站名搜索 + 车次号键盘；公路版什么都没有 | 新增 §4「公路搜索」：地名 / **公路编号键盘** / 景点 / 出入口服务区，四类索引 |
| 5 | 数据生产思路是「按编号抓几条线」 | 覆盖面 0.8%，答非所问 | §3 改成「全国路网三层索引」，先做国道+省道+高速全量 |

### 0.2 v2 的一句话定位

> **铁路版是"全国铁路网 + 车次 + 沿铁路的景点"，公路版就是"全国公路网 + 路线 + 沿公路的景点"。**
> 两者的产品骨架**必须同构**：同样的三层（网 / 搜索 / 沿程内容），同样的交互范式（选起终点 → 出线路 → 翻沿程 → 看详情），只有内容维度不同。

### 0.3 三件主事（主功能），两件从属（内容层）

```
主功能（与铁路一一对应）
  A. 全国公路网      ←→ 铁路：全国铁路拓扑（2,051,051 节点 / 2,253,455 边）
  B. 公路搜索        ←→ 铁路：站名搜索 + 车次号前缀键盘
  C. 任意 OD → 沿程景点 ←→ 铁路：选车次 → 走廊 → 沿程 432 景点匹配

从属内容层（排名在主功能之下）
  D. 排行榜（3+ 类榜单）  ←→ 铁路：热门车次 / 风景走廊榜单
  E. 精品线路书（12 条）  ←→ 铁路：单个走廊的深度路书页
```

## 三、核心能力 A：全国公路网（覆盖 + 可查）

### 3.1 覆盖目标与诚实边界

官方规模（2024 年交通运输行业发展统计公报）：

| 等级 | 里程 | 条数（权威名录） | v2 收录目标 | 说明 |
|---|---|---|---|---|
| 国家高速 | 16.2 万 km | 278 条 | **索引 + 几何 + 拓扑** | 优先，几何质量最好 |
| 普通国道 | 29.9 万 km | **301 条**（12 放射 + 47 纵 + 60 横 + 182 联络） | **索引 + 几何 + 拓扑** | 主战场（政策明确"以普通国道为主体"） |
| 省道 | 41.01 万 km | 各省自定（约 3000+ 条） | **索引 + 几何**，拓扑择要 | 编号跨省重复，主键必须 `省:编号` |
| 县道 | 69.88 万 km | — | **索引 + 几何（按需）** | 几何可查率低 |
| 乡道 | 124.34 万 km | — | 仅索引 | 不建几何 |
| 村道 | 270.14 万 km | — | 不收录 | — |
| **全国合计** | **549.04 万 km** | — | — | — |

**必须写进 UI 的诚实说明**（不能装作什么都有）：
- 高速 / 国道：几何可查率 **85~95%**，拓扑连通可用
- 省道：几何可查率 **50~70%**
- 县道：**20~40%**；乡道村道 **<10%**，只有名称和起止，没有几何
- 数据来源是 OpenStreetMap（众包），**非官方测绘成果**，里程为估算值，需校准
- 政策 12 条精品线官方**尚未发布逐桩走向表**，本产品中的精品线走向为**依据 OSM 编号还原的近似走向**，不是官方线位

页面底部固定一行小字：「路网数据来自 OpenStreetMap 众包数据，里程与走向为估算，不作为导航依据」。

### 3.2 编号主键规范（这是数据层最容易翻车的地方，必须硬编码成校验）

```
国道 G：ref 全国唯一  →  主键 = "G318"
  - G + 1~3 位数字 = 普通国道（G318 沪聂线、G109 京拉线）
  - G + 4 位数字   = 国家高速（G5611 是高速，不是国道）
  - 例外：G + 2 位且 < 100 的（G1~G99）为高速主线（G1 京哈高速）
省道 S / 县道 X / 乡道 Y / 村道 C：省内编号跨省重复 → 主键 = "青海:S101"
```

**校验规则（进库前跑，`scripts/validate-road-keys.mjs`）**：
1. 匹配 `/^G\d{1,3}$/` → `class=national`（普通国道）
2. 匹配 `/^G\d{4}$/` → `class=expressway`（国家高速）
3. 匹配 `/^[SXYC]\d{1,4}$/` → 必须带省前缀，否则拒绝入库
4. 同名不同线（如两条 S101）在跨省交界处必须拆成两段，不得串成一条

### 3.3 三层数据架构（照抄铁路的 L0/L1/L2 分层思路）

```
L0 索引层  data/roads/index/{province}.json      每省 1 份，~250KB，前端按需加载
           └─ [{ key, ref, name, class, province[], fromPlace, toPlace,
                 lengthKm, bbox, geomHash, spotCount }]
           用途：搜索、列表、地图缩放 LOD 判断、编号键盘候选
           前端常驻：只加载「全国索引摘要」（每省 ~40KB，34 省 ≈ 1.4MB，gzip ~350KB）

L1 几何层  data/roads/geom/{key}.json            按 key 懒加载，单条 50~800KB
           └─ { key, points: [lng,lat,elev?][], cumKm: number[],
                nodes: [{name,atKm,type}] }
           用途：画线、投影、沿程匹配、路书章节定位

L2 拓扑层  data/roads/china-road-topo.bin        服务端常驻，不进前端
           magic = "RVRT"（Road Version Topology），格式沿用 RVTP
           CSR：nodeXY(F64) / edgeOffset(I32) / edgeTo(I32) / edgeW(F32)
                / edgeFlag(U8) / edgeLine(U16) + 0.03° 网格索引
           节点：国道 + 高速 + 省道主干的路口/端点（**不含城市内部道路**）
           目标规模：1.5M~3M 节点 / 2M~4M 边 / 80~150MB
```

**为什么拓扑不做全路网（必须把理由写进代码注释）**：
参考公开的 OSM car 网络规模——美国加州单州就有 1613 万节点 / 3433 万边。中国全境 car 网络节点量级在 **3000 万以上**，CSR 常驻内存 >1GB，单次 Dijkstra 在 Node 单线程下无法进 500ms 预算。
**因此 L2 只建「国道 301 条 + 国家高速 278 条 + 各省省道主干」的干线可通行图**，城市内部道路不入库；OD 端点通过网格 snap 吸附到最近干线节点（容差 5km，超限则降级为"端点外接段 + 干线主段"拼接）。这与铁路拓扑 205 万节点同量级，可控。

### 3.4 数据生产流水线

```
Step 1  权威名录（有编号、无坐标）
        · 普通国道 301 条：《国家公路网规划》附表
        · 国家高速 278 条：同上
        · 省道：各省交通运输厅公示名录（爬取 + 人工核对）
        产出 data/roads/authoritative/{national,expressway,provincial}.json

Step 2  OSM 几何（有 ref、无权威名录）
        Overpass：way["highway"]["ref"="G318"]  → out geom;
        备选：rel["route"="road"]["ref"="G318"] → >; out geom;
        端点容差 300m 双向串接（v1 的 chainWays 已实现，直接复用）
        Douglas-Peucker 简化（ε=30m）
        产出 data/roads/geom/{key}.json

Step 3  Join
        authoritative.ref × osm.ref → key
        未命中：记入 data/roads/coverage-gap.csv（缺几何）
        OSM 有而名录无：标 source=osm_only，status=unverified

Step 4  建拓扑
        scripts/build-road-topology.mjs
        - 读取全部 L1 几何
        - 端点/交叉点去重（1e-5 度量化）→ node id
        - 相邻节点成边，权重 = 距离 × 等级系数（高速 1.0 / 国道 1.15 / 省道 1.35）
          —— 系数表示"同等距离下优先走高等级路"，与铁路 typePenalty 同思路
        - 写入 RVRT 二进制 + meta.json

Step 5  质检
        scripts/verify-road-network.mjs
        - 每条国道长度与官方里程偏差 >±25% → 告警
        - 连通分量检测：301 条国道应落在 1 个主分量（含跨省接续）
        - 几何自相交、跳点 >5km 的段 → 标 broken
```

**Overpass 抓取纪律（v1 踩过的坑，必须继承）**：
- 必须带 `User-Agent`；多端点 failover：`maps.mail.ru/osm/tools/overpass`（实测最稳）→ `overpass-api.de` → `overpass.osm.ch` → `kumi.systems`
- 本地磁盘缓存 `data/cache/roads/ways-{ref}.json`，命中不重复请求
- Overpass 的 `geometry` 是 `{lat, lon}` **对象数组**，不是 `[lng, lat]` 元组，必须 `el.geometry.map(p => [p.lon, p.lat])`
- route relation 的 `>;out geom` 会展开**全国整条**超出 bbox，必须按 bbox 过滤 member 后**重新串接**

## 四、核心能力 B：公路搜索（对标铁路的站名 + 车次号）

铁路搜索是「站名（1324 站）+ 车次号（G/D/Z/T/K 前缀键盘）」。公路版对应四类索引，统一入口 `suggestPlaces(q, kind?)`。

### 4.1 四类索引

| kind | 数据源 | 条数目标 | 打分规则 |
|---|---|---|---|
| `place` 地名 | 民政部行政区划（省市县乡镇）+ 高德/天地图 geocode 兜底 | 省 34 + 市 333 + 县 2800+ + 乡镇 3.8 万 | 精确=100 / 前缀=80 / 拼音前缀=70 / 包含=50 |
| `road` 公路编号 | L0 索引 | 国道 301 + 高速 278 + 省道约 3000 | 精确 ref=100 / 前缀=85（输 G31 → G310,G311…）/ 中文名（沪聂线）=60 |
| `spot` 景点 | `roadside-spots.json` | 3 万 | 名称精确=100 / 前缀=80 / 包含=45 |
| `facility` 服务区/互通/收费站/出入口 | Overpass `highway=services` / `motorway_junction` + 各省高速集团名录 | 服务区 ~3000、互通 ~1.2 万 | 名称精确=100 / 包含=50 |

### 4.2 编号键盘（必须做，这是与铁路体验对齐的关键）

对标 `apps/web` 里已有的「车次前缀键盘」（v0.2.4 做过）：

```
┌─────────────────────────────┐
│ G    S    X    Y    C       │  ← 等级前缀（单选，互斥高亮）
├─────────────────────────────┤
│ 1  2  3  4  5  6  7  8  9  0│
└─────────────────────────────┘
```

- 点 `G` → 候选列出全部 G 开头编号（301+278 条，按编号数字升序）
- 继续按数字 → 实时收窄（G3 → G3/G30/G31… → G318）
- 选省道时前缀键 `S` 后**先选省**（因为跨省重复），省芯片排在数字键盘上方
- 输入完成后，直接跳 `/drive/road/G318` 或把该公路设为行程的途经约束

**复用点**：直接抄 `SelectTrip.vue` 里车次键盘的 DOM 结构与 `--space-*` 间距变量，只换数据源和配色（`TRAIN_COLORS` → `ROAD_COLORS`，见 §11.2）。

### 4.3 搜索服务接口

```ts
// apps/api/src/services/roadIndex.ts
export type PlaceKind = 'place' | 'road' | 'spot' | 'facility';
export interface PlaceHit {
  kind: PlaceKind;
  id: string;          // place: 行政码 / road: key / spot: spot.id / facility: osm id
  name: string;        // "G318" 或 "稻城亚丁"
  sub: string;         // "沪聂线·上海→聂拉木" 或 "四川·甘孜"
  lng: number; lat: number;
  score: number;
}
export function suggestPlaces(q: string, kind?: PlaceKind, limit = 20): PlaceHit[];
export function resolvePlace(text: string): PlaceHit | undefined;  // 供 OD 端点解析
export function geocodeFallback(name: string): Promise<PlaceHit | null>; // 高德/Nominatim
```

**降级链（照抄 `geocode.ts` 的容错风格）**：
本地索引命中 → 不请求网络；未命中 → 高德 Web 服务 geocode（需 `AMAP_KEY`）→ Nominatim → 返回 null 并提示"未找到，请点地图选点"。
**必须保留"点地图选点"兜底**，否则乡镇级地名搜不到时产品就断了。

## 五、核心能力 C：任意 OD → 沿程景点加载（本版真正的主体）

用户原话拆解成三个入口，**共用同一套沿程匹配器**：

| 入口 | 触发 | 路线来源 |
|---|---|---|
| C1 **点对点** | 用户填起点 + 终点 | 路径规划引擎出折线 |
| C2 **整条公路** | 用户选 G318 / 某省道 | L1 几何直接就是折线 |
| C3 **我在哪** | 实时 GPS | 历史轨迹 + 前方规划（隧道无信号时纯本地） |

### 5.1 路径规划引擎：双引擎（在线优先 / 本地兜底）

**引擎 1（在线，默认）**：高德 Web 服务「驾车路径规划 v5」
- 请求：`origin=lng,lat` `destination=lng,lat` `key` `strategy`（10 推荐 / 2 距离最短 / 12 躲避拥堵）`waypoints`（支持 16 个途经点）`show_fields=polyline,cost`
- 返回：`route.paths[].steps[].polyline` 拼成完整折线 + `distance` + `duration` + `tmcs`（路况）
- 优点：真实可导航、有限行/收费/避堵、乡镇级也能到
- 缺点：需 Key、有配额、坐标是 **GCJ-02**（必须用已有的 `gcj02ToWgs84()` 转换后才能和 OSM/景点库对齐 —— `packages/shared/src/geo/coordTransform.ts` 已存在）

**引擎 2（本地，兜底 + 鸿蒙端）**：`roadTopology.ts` CSR + A*
- 触发条件：高德超时/失败、用户离线、鸿蒙端隧道无信号
- OD 端点 snap：0.03° 网格找最近干线节点，容差 5km
- 启发式：Haversine 直线距离 / 最高限速 → A*（可采纳）
- 预算：单条 <500ms
- 出折线后**与引擎 1 走完全相同的下游**（见 5.3），保证两种模式下景点结果一致

**为什么必须双引擎**：鸿蒙端 + 隧道无信号是 v1 就定下的硬约束；且高德配额在榜单批量预览场景会打爆。本地引擎不是"降级"，是**必备能力**。

### 5.2 沿程匹配算法（照抄铁路 `filterSpotsAlongRailway` 的签名与输出结构）

```ts
// packages/shared/src/drive/alongRoute.ts   ← 零框架依赖，Web/鸿蒙共用
export interface AlongRouteOptions {
  /** 沿路缓冲半径，默认见下表 */
  bufferKm?: number;
  /** 是否做左右侧判定，默认 true */
  autoSide?: boolean;
  /** 只返回某几类 */
  categories?: string[];
  /** 最少"值得一看"分值，过滤路人 POI */
  minScore?: number;
  maxCount?: number;
}

export interface AlongSpot {
  id: string; name: string;
  lng: number; lat: number;
  /** 在路线上的投影里程（km，从起点算） */
  progressKm: number;
  /** 到路线的垂直距离（km） */
  distKm: number;
  /** 左右侧：left/right/unknown + 置信度 */
  side: 'left' | 'right' | 'unknown';
  sideConfidence: 'high' | 'mid' | 'low';
  category: string;
  score: number;         // 0~100，用于排序与 minScore 过滤
  /** 偏离主路多远需要绕行（km），0 = 就在路边 */
  detourKm: number;
  /** 建议停留（分钟） */
  stayMin?: number;
  intro?: string;
  tier: 'A' | 'B' | 'C';  // A=讲解级 B=沿途可看 C=小确幸
}

export function filterSpotsAlongRoad(
  spots: RoadsideSpot[],
  coords: readonly [number, number, number?][],
  opts?: AlongRouteOptions,
): AlongSpot[];
```

**实现要点（全部复用 v1 已写好的 `packages/shared/src/drive/geo.ts`）**：
- `buildPath(coords)` → 带累积里程的折线
- `computeCumKm(path)` → 累积里程数组
- `projectToRoute(path, lng, lat)` → `{ alongKm, offRouteM, segIndex, tangentHeading }`
- `determineSide(...)` → 叉积定左右
- 排序：`progressKm` 升序

**性能**：折线 N 点 × 景点 M 个的朴素投影是 O(N·M)，300km 路线（简化后 ~1500 点）× 3 万景点 = 4500 万次，太慢。
**必须加网格索引**：把景点按 0.05° 网格（约 5km）分桶，只取路线 bbox 外扩 buffer 覆盖到的格内景点参与投影。实测可把参与量压到 300~800 个，单次 <30ms。
→ `packages/shared/src/drive/spotGrid.ts`（零依赖，纯 JS Map<number, number[]>）

### 5.3 缓冲半径分级（公路与铁路关键差异，必须写死）

铁路是"隔着窗户看"，所以 `on_track 3km / window 8km / distant 35km`。公路能**停下来、能绕路**，所以距离语义不同：

| 语义 | 公路取值 | 说明 |
|---|---|---|
| `roadside` 就在路边 | **0.3 km** | 观景台、停车区、界碑、桥头、小确幸 |
| `detour5` 5 分钟能绕到 | **3 km** | 村寨、观景台、小景点（公路比铁路更值得绕） |
| `detour20` 20 分钟能绕到 | **12 km** | A 级景区、古镇、名村 |
| `distant` 远景可见 | **35 km** | 雪山、大湖、天际线（只提示"能看到"，不引导绕行） |

**`detourKm` 的计算**：`distKm × 2 − 0.3`（往返减去本来就在路边的一点点），向下取整到 0.5km。UI 上直接写"绕行 4.5 公里 · 约 8 分钟"。这个字段铁路版没有，是公路版的核心差异字段，**必须有**。

### 5.4 三种入口下的一致行为

```
C1 点对点：折线 = 规划结果          → filterSpotsAlongRoad(折线)  → 沿程景点流
C2 整条公路：折线 = L1 几何          → 同上（可选按地级市分段，每段单独出标题）
C3 我在哪： 折线 = 已走轨迹 + 前方规划 → 同上，但只推 progressKm > 当前里程 的（即"前方"）
                                    → 由 radar.ts 做车速带过滤（v1 已实现，直接复用）
```

**C3 的车速带规则（v1 已定，不变）**：
- `>80 km/h` 只推 `worthSlowDown`（"值得减速看一眼"）
- `40~80 km/h` 推 `worthSlowDown` + `canPark`
- `<40 km/h` 只推 `canPark`（"这儿能停"）
- 前视距离 `clamp(speedKmh × 0.05, 3, 15)` km

这样，"我在哪条国道上就加载那条国道的景点"和"我从 A 到 B 就加载这条路的景点"是**同一份代码**，不是三套。

```
GET  /api/drive/road/:key                        → 单条公路（L1 几何 + 统计）
```

### 6.3 打分模型（决定"哪些 POI 值得出现"）

```
+ 官方资质：世界遗产 40 / 5A 38 / 4A 30 / 3A 22 / 名镇名村 26 / 传统村落 20 / 国保 24

+ 观景价值：viewpoint +10 / 有 bestView 时段 +5
+ 稀缺性：省内唯一 +8 / 全网罕见标签 +5
```

### 6.4 生产流水线

```
scripts/build-roadside-spots.mjs
  1. 载入权威名录（A 级景区 / 传统村落 / 名镇名村 / 世遗 / 国保 / 红色）
  2. 缺失坐标 → geocode（高德优先，Nominatim 兜底，失败入 missing.csv）
  3. 按省拉 OSM POI（Overpass 34 次，带缓存与 failover）
  4. 与权威名录按 (name, 距离<2km) 去重合并 → 权威优先保留
  5. 打分 + 分类 + 写 data/roads/roadside-spots.json
  6. 建网格索引 data/roads/spot-grid.json
  7. 出质检报告：总数 / 各省分布 / 无坐标数 / 打分分布直方图
```

**诚实风险（必须写进文档和 UI）**：
- 1.57 万家 A 级景区**没有全国统一开放 API**，各省文旅厅公示格式不一，需要逐个省爬/整理，**首期只能覆盖到 4A/5A + 部分 3A（约 4000~6000 家）**，其余靠 OSM 补
- 传统村落 8155 个的官方名单**只有村名和县名，没有坐标**，全部需要 geocode（约 8000 次调用，需分批限流）
- 同名村落在全国极多，geocode 会错配（铁路版已经踩过"潜江被标到江苏"的坑，`geocode.ts` 里的 `STATION_REGION_ANCHORS` 机制要照搬到公路侧：按"县名锚点 + 最大距离"拒收错配）

```ts
  verified?: boolean;
}

/** 合成路线（OD 结果 / 榜单条目指向的路线） */
export interface RoadRoute {
  id: string;

  roadKeys: string[];
  provinces: string[];
  lengthKm: number;
  durationMin?: number;
  coords: RoadPoint[];
  chapters?: { title: string; fromKm: number; toKm: number }[];
  boardIds?: string[];

```

**注意**：v1 已经往 `types.ts` 追加了一批 drive 类型（`DriveGroup` / `DriveTier` / `RoadbookChapter` / `DriveHighlight` / `RadarHit` 等）。v2 的做法是**保留 v1 类型不删**（路书页还要用），**新增**上面这批 `Road*` 类型，命名上用 `Road` 前缀区分，避免与 v1 的 `Drive*` 混淆。
