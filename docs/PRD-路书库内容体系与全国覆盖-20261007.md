| 问题 | 结论 |
|---|---|

| 交接怎么做 | 每阶段自包含：清单 + 数据文件 + 完成判据 + 校验命令 + 遗留清单（见附录 A 交接模板） |

## 1. 产品目标

### 1.1 一句话目标

> **路书库 = 全国可查、点开一眼就能照着走的旅行攻略库。**
> 用户在列表页按省份 / 玩法 / 公路编号 / 主题 / 天数任意维度都能找到东西；点开任意一条，都能看到「几天、多少公里、走哪几条路、每天住哪玩什么、自驾怎么开、无车怎么走」。

## 3. 内容分层模型（本 PRD 的核心）

### 3.1 五层定义

| 层 | 名称 | 一句话定义 | 典型天数 | 参考里程量级 | 现有 | 阶段新增 | **终态** |
|---|---|---|---|---|---|---|---|
| **L1** | 国家级大环线 / 国家长廊 | 跨省级行政区、或具有全国级 IP 的长线，是「一生要走一次」的骨架产品 | 6~20 天 | 700~4000 km | 13 | +30 | **43** |
| **L2** | 区域级省域环线 | 单省内跨 3 个以上地级市，或跨省但行程较短；「一个省怎么玩透」的主力 | 3~7 天 | 250~1200 km | 0 | +63 | **63** |
| **L3** | 城市级 · 单景区深度几日游 | 围绕**一个核心景区/景区群**展开的成品行程，颗粒度到每天几点去哪 | 1~4 天 | 30~400 km | 0 | +90 | **90** |
| **L4** | 城市级 · 周边周末线 | 以**单个中心城市**为圆心、1~2 日可往返的短途 | 1~2 天 | 60~300 km | 0 | +56 | **56** |
| **L5** | 小众城市 / 冷门目的地 | 知名度不高但有独特性的目的地，主打「人少、有料」 | 2~4 天 | 100~600 km | 0 | +34 | **34** |
| — | **合计** | | | | **13** | **+273** | **286** |

### 3.2 判定标准（决策树，按顺序判定）

```
① 是否围绕「一个核心景区 / 景区群」，且主要城市数 ≤ 2？
     └─ 是 → 是否以单个中心城市为圆心、1~2 日可往返、景区只是其中一站？
                ├─ 是 → L4（周末周边）
                └─ 否 → L3（景区几日游）
② 否 → 是否跨 2 个及以上省级行政区？
     ├─ 是 → 是否 days ≥ 5 且 totalKm ≥ 600，或属于全国级 IP（G318/G219/G228/长征/黄河/运河/丝路/环岛）？
     │          ├─ 是 → L1
     │          └─ 否 → L2
     └─ 否（单省）→ 是否 days ≥ 8 或 totalKm ≥ 1200（省内超长线，如新疆东天山、滇西南大环）？
                        ├─ 是 → L1
                        ├─ 否 → 是否覆盖 ≥ 3 个地级市？
                        │        ├─ 是 → L2
                        │        └─ 否 → 目的地是否属于「冷门 / 人少」定位？
                        │                 ├─ 是 → L5
                        │                 └─ 否 → L3 或 L4（按 ① 的圆心判定）
③ 边界情况：省内 1~2 市、2~4 天、目的地冷门 → 一律归 L5（避免 L5 被 L3 吸走）
```

### 3.3 字段填写规则（每条路线必填，机器可校验）

| 层 | `tier` | `layer`（新增字段） | `shape` 常见值 | `primaryMode` 优先值 | `modes` 最低要求 |
|---|---|---|---|---|---|
| L1 | `national` | `L1` | `loop` / `point` / `corridor` | `selfdrive` | ≥ 2 个，含 `selfdrive` |
| L2 | `regional` | `L2` | `loop` / `corridor` | `selfdrive` | ≥ 2 个，含 `selfdrive` |
| L3 | `city` | `L3` | `loop` / `outback` / `point` | `selfdrive`（徒步/骑行线可 `hiking`/`cycling`） | ≥ 2 个；除纯徒步穿越外必须含 `selfdrive` |
| L4 | `city` | `L4` | `loop` / `outback` | `selfdrive` | ≥ 2 个，含 `selfdrive` 与 `public` |
| L5 | `city`（跨市时 `regional`） | `L5` | `loop` / `outback` | `selfdrive` / `mixed` | ≥ 2 个，含 `selfdrive` 或 `public` |

**`shape` 判定补充**：
- `loop` —— 起点 = 终点（`startNode === endNode`）
- `point` —— 起终点不同，且不需要原路返回（异地还车 / 单向交通）
- `outback` —— 起终点不同但需原路进出（如景区大门往返、塔县往返喀什）
- `corridor` —— 沿一条主轴可任意截取（国道长线、运河、边境线），`startNode`/`endNode` 填**建议截取段**的端点，并在 `summary` 说明「可任意截取」

### 3.4 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 路线 `id` | 小写英文 + 连字符，`<核心地理>-<形态/玩法>`；**L3 统一 `<景区>-<天数>d`** | `huangshan-3d`、`shenzhen-dapeng-weekend`、`hainan-island-loop`、`g331-northeast-border` |
| 路线 `name` | L1/L2 用地域名；**L3 必须带「N 日」**；L4 带城市名 + 「周边」 | `黄山 3 日深度游`、`深圳大鹏半岛 2 日`、`海南环岛自驾` |
| `subtitle` | 一句话亮点，20~40 字，写「看什么 + 为什么值」 | `一线串起奇松怪石与徽州古村：前山看松、后山看谷、山下看村` |
| `alias` | 常见别称，便于搜索命中 | `['黄山三日游','徽州三日']` |
| `poi.id` | `<路线前缀>-p-<拼音>`，与现有 13 条一致 | `hs-p-guangmingding` |
| `segment.id` | `<路线前缀>-<序号>` | `hs-1` |
| `anchorCity` | **必须与 `_regions.json` 中某个地级行政区名完全一致**（否则 coverage 回写失败） | `黄山`（不是 `黄山市`） |
| 数据文件 | 一个大区一个文件，**单文件 ≤ 12 条路线**（约 500KB 上限），超出拆 `-part2.json` | `east-china.json` / `east-china-part2.json` |

> ⚠️ **`anchorCity` 拼写纪律**：装载器 `applyRouteCoverage()` 用 `cities / anchorCity` 与 `RoadbookCity.name` 精确匹配回写 `coverage`，**写错一个字就是一条"幽灵城市"**。落库前必须对照 `_regions.json` 核对该省的地级市名列表（`_regions.json` 里是 `黄山`、`深圳`、`延庆区` 这种不带"市/区"后缀可能会有差异 —— 北京写的是 `延庆区`，安徽写的是 `黄山`）。**每个阶段开工第一步：把本阶段涉及省份的城市名表从 `_regions.json` 里 dump 出来当字典。**

### 3.5 `editorRank` 规则建议（避免 13 条大线霸榜）

**现状问题**：13 条大线占用 1~13，新增路线从 14 开始排 → 默认排序（rank 升序）永远把西部大线顶在前面，新补的华东景区线沉底。

**新规则（双层编码）**：

| 层 | `editorRank` 区间 | 说明 |
|---|---|---|
| L1 | **1 ~ 99** | 现有 13 条保持 1~13 不动；新增 L1 从 14 起 |
| L2 | **100 ~ 199** | 省内编号按「热门省优先」排 |
| L3 | **200 ~ 299** | 按景区知名度排（5A 世界遗产优先） |
| L4 | **300 ~ 399** | 按城市能级排（北上广深 → 省会 → 地级市） |
| L5 | **400 ~ 499** | 按独特性排 |

**默认排序改为「分层轮转」**（改动点：`packages/shared/src/travelbook/types.ts` 第 530~534 行 `queryTravelRoutes` 的 `default` 分支）：

```
recommend 排序算法（新增）：
  1. 按 layer 分为 5 组，组内按 editorRank 升序
  2. 按 [L3, L4, L2, L1, L5] 的顺序做轮转，每轮每组取 2 条
  3. 某组取完后跳过，直到全部取完
  → 效果：首屏 10 条 = 4 条景区几日游 + 4 条周末线 + 2 条区域线；
    第 11~20 条开始出现大环线。用户一眼看到「这个库什么都有」。
  4. 保留原 `sort` 枚举不变，新增 sort='layer' 时跳过轮转、纯按 editorRank 升序（给"看全部大线"用）
```

> 该改动是 **P0**，建议与阶段 1 数据同步落地，否则阶段 1 补的 48 条新路线在列表页前 20 条里一条都露不出来。

### 3.6 Schema 增量建议（需架构师确认，见 §8 Q7）

| 新增字段 | 类型 | 用途 | 是否必填 |
|---|---|---|---|
| `layer` | `'L1'\|'L2'\|'L3'\|'L4'\|'L5'` | 内容分层，`tier` 只有三值无法区分 L3/L4/L5 | P0（L3 及以后必填） |
| `themes` | `string[]` | 主题标签：`亲子` / `摄影` / `徒步` / `海岛` / `古城` / `美食` / `避暑` / `冰雪` / `红色` / `边境` | P1 |
| `parentRouteId` | `string` | 母路线 id。用于「G219 总纲 ↔ G219 北段/南段」「省域环线 ↔ 其中某景区几日游」的上下级关联 | P2 |

**迁移**：现有 13 条补 `layer: 'L1'`、`carFreeSummary`，属阶段 1 的 P0 数据治理任务（13 条 × 2 字段，0.5 人日）。

## 4. 玩法维度：自驾优先 + 无车兜底

### 4.1 六种 mode 与新内容的结合方式

| mode | 与分层内容的关系 | 重点投放层 |
|---|---|---|
| `selfdrive` 自驾 | **用户明确要求「自驾线越多越好」**。所有 L1/L2 与绝大部分 L3/L4/L5 都要给自驾方案 + 里程 | 全层，覆盖率目标 ≥ 91% |
| `charter` 包车 | 高原 / 边疆 / 语言不通地区的主流玩法（阿里、新藏、怒江、独龙江） | L1（西部）、L5（边疆） |
| `public` 公共交通 | 无车党刚需。高铁 + 客运班车 + 景区直通车 | L3（名山几乎都有高铁 + 直通车）、L4（城际） |
| `cycling` 骑行 | 环湖、环岛、草原公路 | 海南环岛、青海湖、环洱海、太湖、千岛湖 |
| `hiking` 徒步 | 名山穿越、古道 | 武功山、四姑娘山、稻城亚丁、麦理浩径、雨崩 |
| `mixed` 混合 | 「飞机/高铁抵达 → 当地包车/班车」，是东部短线的真实形态 | L3 / L4 / L5 |

### 4.2 硬性要求（写入验收红线）

> **R1｜一条路线必须同时交代自驾与无车方案。**

具体拆解（审计脚本逐条检查）：

1. **`modes` 必须包含 `selfdrive`** —— 例外仅两类，且必须在 `summary` 说明原因：
   - 纯徒步穿越线（全程步道，如麦理浩径、雨崩）
   - 岛屿 / 城市内部步行线（如鼓浪屿、澳门半岛）
2. **`primaryMode = 'selfdrive'`** 为默认选择；只有该线确实以非自驾为主流玩法时才可设其他值（如稻城亚丁 `hiking`、青海湖 `cycling`）。
3. **`practical.carFree` 必填，且必须包含以下四要素**（缺一即 warn）：
   - 最近的高铁站 / 机场（写清换乘到哪个节点）
   - 关键节点之间的接驳方式（动车 / 客运班车 / 景区直通车，**写班次密度量级**如「每日 6 班」而不是精确到分钟的不确定信息）
   - 若部分节点公交不可达，明确写「XX 段建议包车 / 参加当地一日游」并给出参考时长
   - 一句话结论：「全程无车可行」/「无车可完成 70%，XX 段需包车」/「不建议无车」
4. **`totalKm` + `mileageNote` 必填**：`totalKm` 是自驾主线里程；`mileageNote` 必须说明口径（含/不含绕行支线、含/不含景区内部区间车、是否为估算）。
5. **`days` 与 `plan.length` 必须一致**（现有校验只 warn `intro.days !== days`，需补 `plan.length` 校验）。
6. L4 周末线额外要求：`modes` 必须同时含 `selfdrive` 与 `public`（周末线一大半用户是高铁 + 租车或公交）。

## 5. 内容质量红线（验收标准）

> 总则：**不确定就标注不确定，绝不把估算包装成实测，绝不虚构景点 / 公路编号 / 门票价格。**

### 5.1 禁止项（违反即 error，拒绝入库）

| # | 红线 | 说明 |
|---|---|---|
| X1 | **禁止编造公路编号** | 不确定编号 → `segment.refPending = true`，`roadRefs` 填俗称（如「环湖西路」「景区专用道」）。校验器对 `refPending:true` 放宽编号正则 |
| X2 | **禁止把估算写成实测** | 里程为估算时，`mileageNote` 必须出现「估算」「约」「按 XX 公路里程表推算」等口径词，并在 `sources` 写明推算依据 |
| X3 | **禁止虚构景点 / 虚构门票价格** | `ticketNote` 只写「需实名预约」「旺季建议提前购票」「淡旺季票价不同，以官方为准」这类**不含具体金额**的提示；确需写价格时必须带 `sources` 与「以官方公布为准」 |
| X4 | **禁止虚构精确坐标** | 坐标只填有把握的**主节点**（县城/景区大门/垭口）；不确定的途经点用 `segment.via` 带过，**严禁给 `via` 编坐标** |
| X5 | **禁止虚构班次 / 时刻** | 班车只写「每日 X 班量级」，不写具体发车时刻 |
| X6 | **禁止 `coverage` 手写** | `_regions.json` 的 `coverage` / `routeIds` 由 `applyRouteCoverage()` 回写，任何人不得手改 |
| X7 | **禁止重复 id** | 路线 id、poi id 全局唯一（装载器对重复 id 只 warn，需升级为 error） |
