# RailVista 产品规划路线图

> 基于 v0.1.3 现状盘点，面向「视界hey world」旅行博主 IP 的中长期产品演进方案。
> 编制日期：2026-09-28

---

## 一、现状盘点（v0.1.3 已有能力）

| 模块 | 已落地能力 |
|------|-----------|
| 车次查询 | 12306 代理 → 直达车次列表 → OD 截取 |
| 行程地图 | 高德底图 + GPS/时刻表混合定位（卡尔曼融合）+ 站点校准 + 发车偏移 |
| 精准路线 | OSM Overpass 多镜像竞速 → 段缓存 → 7 级降级链 → 热门 OD 预热 |
| 走廊数据 | 248 条铁路走廊折线（全国覆盖） |
| 景点数据 | 432 处景点，v3 六维分类（geo/nature/culture/history/construct/architecture） |
| 左右侧判定 | 实时叉积定侧 + 置信度 + 反向翻转 + 退化处理 |
| ETA 引擎 | 图定/实时修正 + 1σ 置信半宽 + 夜间标记 |
| 主页 | 排行榜（4 榜单）+ 品牌区 + 最近行程 + 演示入口 |
| 线路详情 | /route/:corridorId → 走廊折线 + 景点分组 + 进入实时地图 |
| 全国地图 | /atlas → 248 走廊 + 432 景点 + 六维筛选 + 热力图 + 聚合 |
| UI 主题 | 夜行列车 Cinematic Ink 暗色主题 + 动效优化 |
| 工程 | pnpm monorepo、shared 类型包、25 项单测、CHANGELOG 规范 |

**核心优势：** 全国铁路走廊几何 + 景点六维数据 + 实时定侧算法，在国内同类产品中独一无二。

## 二、功能路线图（分阶段）

### Phase 1 — 内容深化与体验闭环（v0.2.x，1~2 个月）

> 目标：让「车上打开 → 看到什么 → 拍下来 → 分享出去」形成完整闭环。

| ID | 功能 | 说明 | 优先级 |
|----|------|------|--------|
| P1-01 | 景点富媒体 | 每个景点挂载：实拍照片（博主供图）、短视频片段、语音讲解（TTS 或真人录制） | S |
| P1-02 | 「车窗取景框」 | 进入景点 5km 范围时弹出全屏取景 UI：方位箭头 + 最佳角度 + 拍摄参数建议（快门/ISO/焦段）+ 倒计时 | S |
| P1-03 | 行程时间轴 | 本次乘车自动生成时间轴：经过的景点、拍摄记录、站点打卡，可导出为长图/短视频脚本 | A |
| P1-04 | 离线包 | 按走廊预下载折线 + 景点 + 缩略图，隧道/弱网区无感切换 | A |
| P1-05 | 景点故事卡 | 每个景点 200~400 字深度文案（历史/地理/人文），支持 AI 生成 + 博主审校 | A |
| P1-06 | 天气/光照叠加 | 接入气象 API，在地图上叠加云量、日照角度、黄金时段提示 | B |
| P1-07 | 收藏与行程规划 | 用户收藏线路/景点 → 生成「我的铁路旅行清单」→ 按季节/主题推荐 | B |
| P1-08 | 多语言 | 景点名称与故事卡支持 EN/JP（面向入境游客） | C |

### Phase 2 — 社交与 UGC 生态（v0.3.x，2~4 个月）

> 目标：从「博主单向输出」升级为「社区共创」，沉淀用户资产。

| ID | 功能 | 说明 |
|----|------|------|
| P2-01 | 用户账号体系 | 手机号/微信/华为账号登录；本地数据上云同步 |
| P2-02 | 景点打卡 | 到达景点范围 → 自动/手动打卡 → 生成带坐标+车次+时间的打卡卡片（可分享） |
| P2-03 | 用户投稿 | 上传照片/短视频/文字 → 关联到具体景点 → 博主审核后展示 |
| P2-04 | 同车旅客 | 同一车次+同一区间的用户可看到「同车旅伴」→ 临时聊天室（行程结束自动归档） |
| P2-05 | 铁路里程成就 | 累计乘车里程 → 徽章体系（青藏线全程/京广线纵贯/环岛高铁…）→ 个人主页展示 |
| P2-06 | 线路评分与评论 | 对走廊/景点打分（风景/性价比/推荐季节）→ 排行榜接入真实 UGC 数据 |
| P2-07 | 博主专属频道 | 「视界hey world」认证频道：独家线路解读、拍摄幕后、直播预告 |
| P2-08 | 分享裂变 | 行程卡片/打卡卡片一键分享到微信/微博/小红书/抖音，带回流链接 |

### Phase 3 — 智能与个性化（v0.4.x，4~6 个月）

> 目标：AI 驱动的个性化推荐，提升留存与付费转化。

| ID | 功能 | 说明 |
|----|------|------|
| P3-01 | AI 行程规划师 | 输入「3 天假期 / 想看雪山 / 从成都出发」→ 自动推荐车次+区间+景点+住宿节点 |
| P3-02 | 实时风景预测 | 结合天气+季节+时段+历史打卡数据 → 预测「本次行程最值得看的 Top5 景点」 |
| P3-03 | AI 语音导览 | 接近景点时自动播放语音讲解（TTS + 博主录音混合），支持离线 |
| P3-04 | 智能相册 | 行程结束后自动整理照片 → 按景点/时间/方位分组 → 生成 Vlog 脚本或图文游记草稿 |
| P3-05 | 个性化推送 | 基于用户偏好（六维雷达图）推送新线路/季节限定景点/博主更新 |
| P3-06 | AR 车窗叠加 | （鸿蒙/高端机）摄像头对准车窗 → AR 标注远处山峰/河流/建筑名称与距离 |
| P3-07 | 众包数据校验 | 用户反馈「这个景点看不到了/位置偏了」→ 自动触发数据校验流程 |

### Phase 4 — 平台化与开放（v1.0，6~12 个月）

| ID | 功能 | 说明 |
|----|------|------|
| P4-01 | 开放 API | 向第三方（OTA/地图/出行 App）提供铁路景点数据 API |
| P4-02 | 创作者平台 | 其他旅行博主入驻 → 创建自己的线路专辑 → 分成机制 |
| P4-03 | 企业定制 | 铁路局/文旅局定制线路宣传页 → 白标部署 |
| P4-04 | 插件/小程序生态 | 微信小程序 + 支付宝小程序 + 快应用 |
| P4-05 | 国际线路 | 中欧班列/东南亚铁路/日本 JR 精选线路 |

## 三、内容丰富规划

### 3.1 景点数据扩充路径

| 阶段 | 目标数量 | 来源 | 质量保障 |
|------|---------|------|---------|
| 当前 | 432 | 人工 + Wikidata + OSM | v3 schema 校验 |

| Phase 2 | 3,000+ | UGC 投稿 + 众包校验 | 社区投票 + 博主终审 |
| Phase 3 | 5,000+ | 卫星影像 AI 识别 + 文旅局数据对接 | 多源交叉验证 |

|------|---------|---------|------|

| 山河壮丽 | 成昆线/贵广线/兰新高铁 | 喀斯特地貌、大凉山峡谷、戈壁绿洲 | 全年 |

| 海岸线 | 杭深线/海南环岛/青荣城际 | 海景车厢、潮汐时间、海鲜地图 | 4~10月 |
| 赏花专列 | 武广高铁(樱花)/京沪(油菜)/滨洲(薰衣草) | 花期预测、拍摄机位 | 3~7月 |

### 3.4 数据质量提升计划

1. **alongKm 里程区间补全**：当前 432 景点中仅 11 条有完整 v3 里程字段 → 批量投影计算填充
2. **honors 资质标签**：对接国家 A 级景区名录、世界遗产名录、地质公园名录 → 批量标注
3. **bestView 观赏时段**：结合纬度/海拔/朝向 → AI 推算最佳月份与光照方向
4. **sources 溯源**：每条景点至少 1 个 S/A 级来源（官方文件/学术论文/权威媒体）
5. **verification 状态**：目标 80% 景点达到 `verified` 或 `probable`

## 四、鸿蒙 ArkTS 端规划

### 4.1 技术选型

| 层 | 方案 | 说明 |
|----|------|------|
| UI 框架 | ArkTS + ArkUI (Stage 模型) | HarmonyOS NEXT 原生，非兼容 Android |
| 地图 | 华为 Petal Maps SDK (Map Kit) | 替代高德；支持 3D 地形、AR 导航 |
| 定位 | Location Kit (GNSS + 网络融合) | 后台持续定位需申请 `ohos.permission.LOCATION_IN_BACKGROUND` |
| 网络 | @ohos.net.http / RCPSocket | 复用现有 Hono API，无需后端改造 |
| 状态管理 | @State/@Link/@Provide + AppStorage | 对应 Web 端 Pinia store |
| 离线 | RelationalStore (SQLite) + 文件缓存 | 走廊折线/景点/缩略图预下载 |
| 推送 | Push Kit | 景点临近提醒、行程变更通知 |
| 卡片 | Form Kit (服务卡片) | 桌面展示「下一处风景」实时卡片 |
| 语音 | Core Speech Kit (TTS) | 离线语音导览 |
| AR | AR Engine (SceneKit) | Phase 3 的 AR 车窗叠加 |
| 分享 | Share Kit | 打卡卡片分享到微信/华为分享 |

### 4.3 鸿蒙特有能力（差异化）

| 能力 | 说明 | 对应 Web 端 |
|------|------|------------|
| 服务卡片 (Widget) | 桌面 2×2 卡片实时显示「距下一景点 X km / 左侧车窗」 | 无（Web 无法常驻桌面） |
| 实况窗 (Live View) | 锁屏/通知栏持续显示行程进度条 + 下一站 | 无 |
| 后台定位 | 息屏后持续 GPS 融合 → 到景点自动推送 | Web 端切后台即停 |
| 多设备协同 | 手机 → 平板/车机流转行程（华为全家桶） | 无 |
| 意图框架 | 小艺语音「帮我看看这趟车经过什么景点」→ 直达 RailVista | 无 |
| 原子化服务 | 免安装、扫码/碰一碰即用（车站二维码引流） | 无 |
| 健康/运动联动 | 乘车里程 → 华为运动健康「旅行里程」数据源 | 无 |

### 4.4 开发里程碑

| 阶段 | 周期 | 交付物 |
|------|------|--------|

### 4.5 关键风险与对策

| 风险 | 对策 |
|------|------|
| Petal Maps 无铁路折线图层 | 自行绘制 Polyline（已有 248 条走廊数据）；底图仅用标准地图 |
| 后台定位权限审核严格 | 准备「导航类 App」材料 + 用户可见的持续通知 |
| ArkTS 与 TS 子集差异 | shared 包避免 DOM/Node API；用 `strict` 模式提前验证 |
| 12306 接口在鸿蒙端跨域 | 统一走自建 API 代理（已有 apps/api），端侧无跨域问题 |
| 华为账号登录 | 接入 Account Kit；同时保留手机号验证码兜底 |

### 5.2 C 端订阅（核心收入）

| 层级 | 价格（建议） | 权益 |
|------|-------------|------|
| **免费** | ¥0 | 基础行程地图 + 站点 + 3 条精品线路景点 + 排行榜 + 全国地图浏览 |
| **Pro 会员** | ¥18/月 或 ¥168/年 | 全部 248+ 线路景点解锁 / 离线包 / AI 语音导览 / 车窗取景框 / 行程时间轴导出 / 无广告 / 专属徽章 |
| **家庭会员** | ¥28/月 或 ¥268/年 | Pro × 4 设备 + 亲子模式（景点科普动画）+ 家庭行程共享 |
| **学生优惠** | ¥9/月 或 ¥88/年 | Pro 权益（需学生认证）|

**转化策略：**
- 首次进入非免费线路 → 展示 3 个景点预览 + 「解锁全部 XX 处风景」CTA
- 行程结束 → 生成精美时间轴长图（带水印）→ 「去水印/导出高清」引导付费
- 打卡满 10 次 → 赠送 7 天 Pro 体验

## 六、技术架构演进

### 6.1 当前 → 目标

```
当前 (v0.1.3):
  [Vue 3 SPA] → [Hono BFF] → [12306 / OSM / 高德]
       ↕
  [localStorage]

目标 (v1.0):
  [Vue 3 Web]  [ArkTS 鸿蒙]  [微信小程序]  [原子化服务]
       ↕            ↕              ↕             ↕
  ┌────────────────────────────────────────────────────┐
  │              API Gateway (Hono / Kong)              │
  ├────────────────────────────────────────────────────┤
  │  行程服务 │ 景点服务 │ 用户服务 │ 内容服务 │ AI服务 │
  ├────────────────────────────────────────────────────┤
  │  PostgreSQL + PostGIS │ Redis │ OSS │ 向量DB │ CDN  │
  └────────────────────────────────────────────────────┘
       ↕            ↕            ↕
  [12306 API]  [OSM/Overpass]  [气象API]  [LLM]
```

### 6.2 后端演进要点

| 当前 | 演进方向 |
|------|---------|
| 文件系统读 JSON（data/presets） | PostgreSQL + PostGIS（空间查询） |
| 无用户体系 | JWT + OAuth2（华为/微信/手机号） |
| 无 CDN | 景点图片/离线包上 OSS + CDN |
| 单实例 Hono | 容器化 + 水平扩展（行程高峰期） |
| localStorage | 云端同步 + 本地缓存双层 |
| 无消息队列 | Redis Stream / RabbitMQ（UGC 审核、推送） |
| 无 AI 服务 | 接入 GLM/GPT API → 景点生成/行程规划/语音 |

### 6.3 shared 包跨端复用策略

```
packages/shared/          ← 纯 TS，无平台依赖
├── types.ts              ← Web + 鸿蒙 + 小程序 共用类型
├── schedule/             ← 进度/ETA/定侧算法 共用
├── geo/                  ← 坐标转换 共用
└── version.ts            ← 版本号 共用

鸿蒙端通过 ohpm 本地包 或 HAR 模块引用 shared 编译产物。
小程序端通过 npm 构建引入。
```

## 七、竞争壁垒与护城河

| 壁垒 | 说明 |
|------|------|
| **数据资产** | 248 条走廊精准折线 + 432→5000+ 景点六维数据，国内无公开替代品 |
