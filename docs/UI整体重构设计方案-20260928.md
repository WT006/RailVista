## 2. 问题清单

### 2.1 P0 — 阻断级

#### BUG-01 滚动链被全局锁死（同步后：滚轮已恢复，键盘仍失效）

> **测量方法说明**：JS 合成的 `WheelEvent` **不会**触发浏览器原生滚动，
> 必须用 CDP `Input.dispatchMouseEvent({ type: 'mouseWheel' })` 发送真实输入才能判定。
> v1 用合成事件得出的「滚轮完全无效」结论因此不可靠，v2 已改用真实输入复测。

- **当前实测（同步后，`probe-sync-*`）**：

  | 通道 | 结果 |
  | --- | --- |
  | 滚轮 / 触控板 | ✅ **已恢复**，四断点 `body.scrollTop` +934 ~ +1500 |
  | 键盘 PageDown | ❌ **仍失效**，四断点变化量均为 `0` |
  | `html` | ❌ 仍 `overflow-y: hidden`，`canScroll: false` |

- **真正的根因（与 Lenis 无关）**：

  1. **`map.css` 全局污染**（主因）：
     `apps/web/src/styles/map.css:18` 为地图页写了 `html, body { height: 100%; overflow: hidden; overscroll-behavior: none; }`，
     而 `base.css` 第 1 行 `@import './map.css'` —— **这条规则被应用到每一个页面**，包括选行程页。
     → `html` 被锁死，`document.scrollingElement === 'html'` 因此失去滚动能力，**键盘滚动必然失效**。
  2. **`body` 被 `has()` 提权成唯一滚动容器**：
     `base.css` 的 `body:has(.select-page) { overflow: auto }` 覆盖了 `map.css` 的 `hidden`，
     于是 `body` 成了唯一能滚的容器（`scrollHeight 2046 / clientHeight 900`），滚轮才得以恢复。
     这是一次"歪打正着"的修复，并非有意为之。
  3. **`.select-page` 自身的 `overflow: auto` 是死代码**：
     它高度为内容高（2046px），自身 `canScroll: false`，从未真正滚动过。
  4. **历史叠加项（已随同步消失）**：
     同步前的 `heyworldchannel-dev` 上还有 Lenis（`useLenis()`）以 `wrapper: window` 初始化并对 wheel 做 `preventDefault()`，
     平滑滚动打在不可滚动的 `html` 上、原生滚动又被拦截，造成"完全无法滚动"。
     **远端 `6a85e03` 已移除 Lenis**（`package.json` 依赖、`useLenis.ts`、引用全删），滚轮随之恢复。

- **因此仍需修的问题**：
  - 键盘 PageDown / Space / Home / End 全部无效（`html` 仍锁死）；
  - 移动端与辅助技术的滚动路径同样依赖 `document.scrollingElement`，存在同类隐患；
  - 滚动容器是 `body` 而非 `document`，滚动位置记忆、锚点、`scroll-behavior` 均不可靠。

- **修复方向（已验证可行）**：
  把 `map.css` 里对 `html, body` 的锁**收回到地图页作用域**（用 `body:has(.trip-page)` 之类的按页路由分流），
  让 Select / Route 页回归「文档流 + 单一滚动容器 = `document`」。
  同步前用候选 CSS 注入真实页面验证过：`html.overflowY` 变 `auto`、`scrollHeight 2081 > clientHeight 900`、滚动立即生效。

> 地图页（`/trip`）依赖全屏不滚的地图壳（`.trip-page`）。
> 因此修复**不能简单删除 `map.css` 的锁**，必须按页路由分流（见 §4.2）。

## 3. 改版思路

### 3.1 一条主线：从「各自为政的模块」到「同一个栅格里的卡片」

当前每个模块各自声明 `max-width` + `margin: 0 auto`，这是四条左基线错位的根因。

改版后：**页面只提供一个容器 `.rv-shell`，所有模块都是它的直接子元素**，模块自身不再声明宽度。

```html
<div class="rv-page">
  <ChinaBackdropMap />          <!-- 背景层，fixed -->
  <AppTopBar />                 <!-- 顶部导航（Logo / 版本 / 动作） -->
  <main class="rv-shell">
    <section class="rv-card">开始查询</section>
    <div class="rv-grid">
      <div class="rv-col-7">
        <section class="rv-card">当前行程</section>
        <section class="rv-card">最近访问</section>
      </div>
      <div class="rv-col-5">
        <section class="rv-card">中国最美铁路</section>
      </div>
    </div>
  </main>
</div>
```

```css
.rv-shell {
  width: min(100% - 2 * var(--gutter), var(--shell-max));
  margin-inline: auto;
}
```

**几何上保证左基线唯一**：容器宽固定 → 所有子元素左边缘必然重合，无需再靠人眼对齐。

### 3.2 响应式：HarmonyOS 断点 + 短视口横屏修正

采用 HarmonyOS/ArkUI 的窗口宽度断点（便于后续 ArkTS 复用同一套规则）：

| 名称 | 窗口宽度 | 典型设备 |
| --- | --- | --- |
| `sm` | 320 – 599 | 手机竖屏 |
| `md` | 600 – 839 | 手机横屏、小平板 |
| `lg` | ≥ 840 | 平板横屏、桌面 |

**关键补充：宽度断点不足以识别"手机横屏"**。844×390 按宽度落在 `lg`，但它其实是手机横屏，需要紧凑布局。
因此叠加**短视口修正**：

```css
@media (orientation: landscape) and (max-height: 560px) { /* 紧凑横屏模式 */ }
```

### 3.3 布局矩阵

| 断点 | 容器 | 栅格 | 布局 | hero/App Bar |
| --- | --- | --- | --- | --- |
| sm 竖屏（320–599） | fluid，gutter 16 | 12 列 = 1 栏 | 单列纵向：查询 → 最近访问 → 排行榜 | App Bar 高 56，Logo 横排压缩版 |
| 紧凑横屏（h ≤ 560 且 landscape） | fluid，gutter 16 | 12 列 = 7 + 5 | **双栏**：左（查询 + 最近访问）／右（排行榜，独立滚动） | App Bar 高 48，标题与副标题折叠为一行 |
| md（600–839） | fluid，gutter 20 | 12 列 = 7 + 5 | 双栏；排行榜 `position: sticky` | App Bar 高 56 |
| lg（840–1199） | max 960 | 12 列 = 7 + 5 | 双栏；左右各自可独立滚动 | App Bar 高 64 |
| xl（≥1200） | max 1120 | 12 列 = 7 + 5 | 双栏；右侧榜单固定高度内滚 | App Bar 高 64 |

**针对"横屏分块割裂、留白不均"的三条具体措施**：

1. **横向利用**：横屏把"输入"和"浏览"分成左右两条独立视线，查询面板不用再往下滚 3.5 屏。
2. **高度预算**：横屏把 hero 折算进 App Bar，主内容区高度预算从 `390 - 171 - ...` 变为 `390 - 48 = 342`，首屏即可见查询区完整表单。
3. **元素按栅格比例生长**：`.rv-col-7 / .rv-col-5` 用 `grid-template-columns: repeat(12, 1fr)` + `span 7 / span 5`，
   宽度随容器等比缩放，不出现固定 px 造成的"某断点突然挤在一起"。
   `min-width: 0` + `overflow-wrap: anywhere` 兜底，杜绝溢出。

### 3.4 组件分层（三级，避免过度抽象）

| 层 | 说明 | 圆角 | 阴影 |
| --- | --- | --- | --- |
| `rv-shell` | 页面容器，只管宽度与栅格 | — | — |
| `rv-card` | 模块级卡片（查询面板 / 最近访问 / 排行榜 / 当前行程） | 16px | elev-2 |
| `rv-tile` | 卡片内的条目（列车卡 / 榜单大卡 / 最近访问行） | 12px → **按 HarmonyOS 档位取 8px** | elev-1 |

> 不引入新的 UI 组件库，`.rv-card` / `.rv-tile` 作为 CSS 类存在，避免改动面扩大。

## 4. 设计规范（Tokens 重写）

以下所有数值落进 `apps/web/src/styles/tokens.css`，业务代码**只允许引用令牌，禁止硬编码色值/圆角/间距**。

### 4.1 断点与栅格

```css
:root {
  --bp-sm: 600px;  --bp-md: 840px;  --bp-lg: 1200px;
  --gutter: 16px;          /* sm */
  --shell-max: 100%;       /* sm */
}
@media (min-width: 600px)  { :root { --gutter: 20px; --shell-max: 720px; } }
@media (min-width: 840px)  { :root { --gutter: 24px; --shell-max: 960px; } }
@media (min-width: 1200px) { :root { --gutter: 24px; --shell-max: 1120px; } }
```

### 4.2 间距（8px 基线，对齐 HarmonyOS 8vp 网格）

统一收敛为 8 的倍数，删除现有的 6 / 10 / 14 等杂值：

```css
--space-1: 4px;  --space-2: 8px;   --space-3: 12px; --space-4: 16px;
--space-5: 24px; --space-6: 32px;  --space-8: 48px; --space-10: 64px;

--gap-inline: var(--space-2);    /* 行内元素 */
--gap-stack:  var(--space-3);    /* 卡内元素 */
--gap-card:   var(--space-4);    /* 卡与卡（sm） */
--gap-card-lg: var(--space-5);   /* 卡与卡（md+） */
--pad-card:   var(--space-4);    /* 卡内边距（sm） 20px → 取 16 */
--pad-card-lg: 20px;             /* 卡内边距（md+） */
```

### 4.3 圆角（对齐 HarmonyOS 官方档位）

依据 HarmonyOS 官方「圆角参数」文档，系统通用档位为 4 / 8 / 16 / 20 / 32 vp：

### 4.7 动效

时长按 HarmonyOS 转场分档（200 / 250 / 300ms），曲线优先弹性：

```css
--dur-micro: 100ms;  /* 颜色/描边 */
--dur-fast:  200ms;  /* 小构件状态切换 */
--dur-base:  250ms;  /* 卡片悬停、Tab 切换 */
--dur-slow:  300ms;  /* 页面转场 */
--dur-enter: 400ms;  /* 首屏入场 */

--ease-standard: cubic-bezier(0.2, 0, 0.2, 1);    /* HarmonyOS 标准曲线 */
--ease-emphasized: cubic-bezier(0.4, 0, 0.2, 1);
--ease-spring: cubic-bezier(0.34, 1.2, 0.64, 1);  /* 弹性（微缩放） */
```

全局保护：

```css
@media (prefers-reduced-motion: reduce) { /* 全部动画降为 0.01ms */ }
@media (hover: none) { /* 关闭全部悬停效果，避免触屏残留 */ }
```

### 4.8 交互态规范（DeepSeek 式悬停三件套）

以 `rv-card` / `rv-tile` 为对象，鼠标移入 250ms 内完成：

| 层次 | 效果 | 实现 |
| --- | --- | --- |
| ① 光影流转 | 卡面内一层跟随鼠标的径向光晕（半径 320px，白色 6% → 透明）；顶部 1px 高光带随鼠标横向扫动 | `--mx` / `--my` 由 `pointermove` 写入，`background: radial-gradient(320px circle at var(--mx) var(--my), rgba(255,255,255,.06), transparent 60%)` |
| ② 微缩放 | `transform: scale(1.008) translateY(-2px)`，曲线 `--ease-spring` | `transition: transform 250ms` |
| ③ 渐显反馈 | 描边由 `--line-hairline` → `--line-accent`；卡内隐藏的次级动作（如"查看线路 ›"）`opacity 0 → 1` + `translateX(-4px) → 0` | `transition: opacity/border-color 200ms` |
| ④ 结构光 | hover 时叠加 `--glow-accent` 外发光，与 `--elev-2` 平滑过渡 | `box-shadow` 过渡 |

性能约束：

- 光晕用 `background-image` + CSS 变量，**不用 `filter: blur()`**、不做 `will-change: transform` 的长期占位（仅 hover 期间）；
- `pointermove` 用 `requestAnimationFrame` 合帧；卡片数量多时按 `:hover` 只在当前卡片上监听（事件委托 + `closest()`）；
- 触屏 / `prefers-reduced-motion` 下全部退化。

## 6. 背景中国地图方案

### 6.1 合规前置说明

按要求参考的项目所在地图规范：

- 边界数据来源限定在合规白名单服务商（高德 / 腾讯 / 百度 / 天地图）。本项目已使用高德（`VITE_AMAP_KEY`），**继续沿用高德**，不引入境外瓦片源。
- 冻结前必须人工校核：**台湾省、海南省（含南海诸岛）、藏南、钓鱼岛及赤尾屿**的画法符合国家标准。
- 不标注军事禁区、涉密单位；不使用境外地图源的样式模板。

### 6.2 实现（推荐方案 A：离线静态轮廓）

| 步骤 | 做法 |
| --- | --- |
| 1 | 新增 `scripts/build-china-outline.mjs`：一次性调用高德 `DistrictSearch`（`subdistrict: 0, extensions: 'all'`）获取 34 个省级行政区边界 |
| 2 | Douglas-Peucker 简化（容差 0.05°）+ 丢弃面积过小的岛屿环 → 合并为单条 `<path>` |
| 3 | 冻结为 `apps/web/src/assets/china-outline.svg`（预估 40–60KB，gzip 后约 15KB），**随包发布，零运行时请求** |
| 4 | 人工校核一次边界画法后方可提交 |

**备选方案 B**：直接挂高德底图（`interactions: disabled` + 暗色样式 + 低透明度）。
优点是不用自绘；缺点是首屏多一次 SDK 加载（约 200KB+），且需要一个固定高度的 WebGL 容器。
**若确认走 B，我会在报告确认后再实施。**

### 6.3 热力层（复用全国铁路景点数据）

- 数据源：`data/presets/scenic-spots.json`（**432 条**，经度 76.08–129.35、纬度 18.30–49.20，覆盖全国）。
- 渲染：离屏 `Canvas 2D` 一次性绘制 —— 每个景点按密度换算半径 2–6px 的径向渐变白点，叠加成"光斑地图"；Web Mercator 投影，`devicePixelRatio` 感知。
- 复用方式：与 `AtlasMap.vue` 共用同一份点位数据，不重复维护；首页只画静态图，不加载高德地图实例。
- 强度分层：按 `category`（mountain / gorge / lake / desert / grassland / engineering / other）给不同色相权重，
  与图例配色保持一致，避免"热力图"变成无意义的白团。

### 6.4 交互

| 触发 | 效果 | 约束 |
| --- | --- | --- |
| 鼠标移入地图区域 | 全局径向高光跟随鼠标（半径 360px，品牌金 8% → 透明） | 地图层 `pointer-events: none`，靠 `window.pointermove` 驱动，**不抢前景事件** |
| 鼠标接近景点（120px 内） | 该批光点提亮 + 描边，其余压暗至 0.35 | 空间索引（按 2° 网格分桶）避免每帧全量遍历 432 点 |
| 悬停模块卡片时 | 背景地图轻微 parallax（`translate 2–4px`）+ 高光收敛 | 与卡片悬停共用同一个 rAF 循环 |
| 触屏 / `prefers-reduced-motion` | 全部关闭，只保留静态淡图 | — |

### 6.5 可读性保障

- 地图整体不透明度 **6%–9%**（`--backdrop-map-opacity`），并按视口加 `mask-image` 径向渐隐，避免与前景文字争夺注意力。
- 地图层 `z-index: -1` + `position: fixed`，**不参与滚动**，滚动时前景移动产生纵深错觉。
- 所有前景卡片为不透明表面（`--surface-1`），叠加地图时正文对比度仍 ≥ 4.5:1（验收时实测）。
