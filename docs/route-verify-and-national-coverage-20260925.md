## 二、"昨天完全没改"的真相：三重环境问题

### E-1 你的电脑上同时跑着两套 API，打架了
实测进程清单（17:47 时点）：
- **PID 33816：一个"无 watch"的 tsx 实例占着 3000 端口**——它 17:47:42 才启动，之前一直是个**更早启动的旧代码实例**在服务。你今天 17:53 发消息说"还是不行"，你测的时刻大概率落在旧实例服务期内。
- **PID 33364/33496/35112：三个 `tsx watch`（pnpm dev）实例全部处于崩溃循环**——因为 3000 被占（EADDRINUSE），**它们一次都没成功监听过**。也就是说你的 `pnpm dev` 里的 API 从来没提供过服务，真正在服务的一直是那个"野实例"。
- vite 前端代理固定指向 `127.0.0.1:3000` → 前端永远打到"野实例"。

### E-2 前端 IndexedDB 缓存没有失效机制
`apps/web/src/lib/tripCache.ts` 把每次行程（含旧示意线几何）持久化在 IndexedDB，key=车次|日期|区间，**几何质量升级后旧快照不会自动作废**。你昨天查过的广州南→珠海北，今天打开直接恢复昨天的示意线，不重新请求。

### E-3 GLM 的审计工具是坏的、且从未运行
- `scripts/audit-routes.mjs` 请求的是 `POST /rail-geometry`，但 API 实际挂在 **`/api` 前缀下**（`basePath('/api')`）——就算跑了也全部 404。
- 它的修复报告"未完成项"里自己写了"C1 需重启 API 后运行"——**它从没跑过端到端验证**，所谓 ✅ 全部是 tsc/build/单测这类静态检查。
- **这是"指令失败"的核心教训：我上一份文档给了修复项，但没有给出"必须起服务、跑指定案例、贴出输出"的强制验收命令，静态检查就能交差。**

## 四、仍然存在的真问题（全国覆盖的拦路虎）

- **R-A 长线慢且不完整**：Z201 244 秒才出 11/13——瓶颈是逐段打 Overpass（进程内实测大量 `TimeoutError`/`HTTP 504`，12 秒超时对大查询太短，Overpass status 端点快不代表查询快）。**凡依赖 Overpass 的兜底在国内网络都不可靠。**
- **R-B 前端缓存**：见 E-2。
- **R-C 无经停长线必败**：只发起终 2 站时，唯一一段 2500km，本地贪心拼线数学上注定失败（实测日志：detour ratio 1.91 abort / end far 153km abort / 在 23190 条轨段中迷路）。**必须带全经停。**
- **R-D 本地图"整趟寻路"缺失**：本地已有 9.1 万段高铁 + 33 万段普速轨网（china-rail.graph），但目前只做"段内贪心"，没有"全图一次寻路"。这是覆盖全国的最后一块架构拼图。
- **R-E 站坐标仍缺 2283 个**：3388 站只有 1105 个有坐标，缺的站会被 resolveStops 静默过滤 → 段缺失 → 降级示意。
- **R-F 走廊孤岛**：shenji/suijia/binbei 质量尚可但没接入主干网；zhanhai/guangshen 半截。K512 能通是靠 B2 兜底绕过去的，不是走廊本身修好了。

## 五、覆盖全国方案（按此顺序执行）

### P0（先做，1 次会话内可完成，解决"看不到效果"）
1. **进程治理**：杀掉 33816 和 3 个崩溃的 watch 实例，只保留一个 `pnpm dev`（tsx watch 模式，改代码自动生效）。给 `/api/health` 加版本指纹（git commit 短码 + 走廊文件数），前端设置页显示"API 版本"，一眼看出打的是新是旧。
2. **前端缓存失效**：`TRIP_CACHE_VERSION` 1→2（旧快照全部作废）；`railwaySource === 'station'` 的快照不作为"精确结果"恢复；结果栏保留明显的"重新生成精确路线"按钮。
3. **经停自动补全（长线成败关键）**：服务端在 `stops.length < 5 && trainCode 存在` 时自动调 12306 经停补全再进 job（Z201/K512 实测证明带经停就能出精确线）；同时把经停查询（/api/trains/stops）加 20s 超时兜底（本次实测它有超时）。
4. **修 audit-routes.mjs**：所有路径加 `/api` 前缀；跑通 10 个车次并把输出贴进修复报告——**今后任何修复交付必须附端到端实测输出，禁止只用 tsc/build 交差**。

### P1（覆盖全国的支柱，1~2 次会话）
5. **站坐标全量补齐**：`seed-stations-geo-full.mjs` 已经写好（三级策略：手工表→轨图 way 投影→走廊折线投影，全本地、无需外网），把 3388 站全部跑完；`patrol-data.mjs` 加硬门禁：**覆盖率 <99% 即 fail**。
6. **整趟本地图寻路（架构基石）**：在 china-rail.graph 的 33 万段轨网上实现 A*/Dijkstra 全局寻路（节点=轨段端点，边长=实际长度，起点=发站投影、终点=到站投影），**一次算出全程沿轨折线，彻底摆脱 Overpass**。贪心拼线降级为段内精修。预计单次查询秒级，全国任意 OD 均可出"真实轨道"级路线。
7. **Overpass 治理**：超时 12s→25s；失败快速跳过不重试；`tryWholeTripFallback` 在本图寻路成功后整体跳过；加开关 `RAIL_OVERPASS=auto`（失败 2 次自动进入纯本地模式）。
8. **走廊连通性门禁**：`patrol-data.mjs` 增加"全网连通图检查"——每条走廊必须与主干网（按走廊折线最近点 ≤12km 或共享 hint）连通，孤岛走廊标记 `island:true` 并强制列表展示，杜绝"建了但永远用不上"的假交付。

### P2（质量收尾）
9. **走廊重做清单**：guangshen 补到深圳（京九↔广深 43km 断口）、zhanhai 完整化（湛江→雷州→海安，hints ≥4）+ 海峡衔接（海安↔海口 36.8km 用轮渡示意段或 bridge 规则显式放行）、shenji/suijia 接入主干、xiangyu 重制（T237）。
10. **GLM 指令模板硬化**（给你直接复用）：每条任务必须包含 ①精确文件与函数 ②可执行验收命令 ③预期输出样例 ④"禁止以 tsc/build/单测替代端到端验收，交付必须粘贴实测输出"。

### 验收标准（下次交付时逐条对照，全部满足才算完成）
```
1. node scripts/patrol-data.mjs --strict          → 0 WARN（站坐标 ≥99%、无未标记孤岛走廊）
2. node scripts/audit-routes.mjs（起服务后）       → 10 车次全部 corridor/network/mixed≥0.8，输出贴报告
3. 北京西→三亚（带经停）                            → ≤60s，qualityTier≥mixed 且 segmentsOk/total ≥ 12/13
4. 广州南→珠海北                                    → corridor 级，≤1s
5. /api/health 返回版本指纹                          → 前端可见
6. 杀掉 API 进程重启后再测 3 个案例                  → 结果不变（缓存不依赖进程内存）
```
