## 三、本轮固化的产线（每一步都有脚本，不靠手感）

一条路线从选题到落库 6 步，全部离线可复算：

1. **选题**：`tmp/rk.py 省份` → 该省现有条数、各地级命中、本层号段占用。优先补条数最少、地级覆盖最少的省。
2. **坐标与等级核验**：`tmp/poifind.py 关键词` → 从 `data/roads/roadside-spots.json`（36893 条）+
   `data/presets/scenic-spots.json`（811 条）里取**已核验**点位，输出 `lng,lat 城市 名称 [tier/评级] 开放 亮点 资质`；
   县城/地级中心点用 `data/roads/places-admin.json`（3564 个行政中心）。命中不了就不写坐标，改走 `segment.via`。
3. **编号合法性**：`node scripts/roadbook-lookup.mjs check G344`（子命令 `poi/place/roads/check/cities/rank`）。
   三表：`data/roads/index/{national,expressway,provincial}.json`。不在册 → 只能写俗称 + `refPending: true`，**禁止编编号**。
4. **里程实算**：`pnpm roadbook:measure tmp/m-X.json tmp/m-X-out.json`（= `scripts/roadbook-measure.mts`，
   在 `data/roads/china-road-topo.bin`（1498548 节点 / 3706263 边）上跑 A*）。**取值规则**：
   - 实测/直线 比值 ≤1.6 → 直接用实测值；
   - 比值 >1.6 或 `engine=direct`（本地无解）→ 改按直线 ×1.3-1.35 推算；
   - **两种口径都要在 `mileageNote` 里逐段交代**：采用值、被弃用的实算值、对应比值。这是 PRD 红线 X2（不许把估算写成实测）。
   - `totalKm` 口径：`Σplan` 必须与 `totalKm` 相等（判据 C，容差 ≤1km）；`Σsegment` 允许偏离 ≤25%，
     城内短驳、往返取景这类「不成段」的量放 plan 不放 segment（本轮 L2/142 就是 Σplan 681 / Σseg 661，差 20km 城内短驳，已在 `mileageNote` 说明）。
5. **写稿**：一次一条，**先写 `tmp/route-x.json`，再用 Python 合并进目标文件**（见 §4 坑 1）。
   新路线一律进新建 `segments-*.json`，**不动 10 个 LEGACY 存量文件**。
6. **验收**（三件套，顺序不限但都要跑）：
   - `PYTHONUTF8=1 python tmp/selfcheck.py <新文件> <其他新文件…>` —— Σplan/Σseg/天数/POI 悬空/号段/单日里程上限/钱与时刻/未引用 POI/跨文件 rank 重复；
   - `node scripts/build-roadbook-index.mjs` —— 全库判据 A~G + shared V1~V19；
   - `node scripts/roadbook-scan-garbage.mjs <文件>` + `node scripts/roadbook-scan-content.mjs <文件>`。

**单日里程上限**（本轮沿用）：L1/L2 ≤300km、L3/L5 ≤250km、L4 ≤150km。
**文案长度**：`lodgingNote` / `foodNote` 60-90 字（硬上限 120），**不写金额、不写钟点**；`carFree` ≥20 字且含
「高铁/机场 + 市内接驳 + 景区专线 + 结论」四要素；每个 POI 必须有 `ticketNote`；`plan[].summary` ≥60 字 + `tips`。

## 五、内容三渠道怎么落到字段里

主理人给的采集口径是三条渠道，本轮的映射方式（下一批保持同一写法，否则 `sources` 会空心化）：

| 渠道 | 用来定什么 | 写在哪 |
|---|---|---|
| OTA（携程/飞猪/同程/去哪儿）经典跟团线 | 天数结构、停留顺序、住宿落点、是否值得单列一地 | `sources[].usedFor = 「X 日结构与景区换乘、住宿落点顺序」` |
| 小红书与自媒体攻略 | 美食具体到菜名、排队与限流体验、拍摄时段、避坑 | `practical.foodNote` / `bookingNote` / `plan[].tips` |
| 文旅公众号与官网、文物与水利部门公告 | 等级与名录、预约与限流规则、汛期与封山公告 | `pois[].ticketNote` / `intro.seasonNotes` / `practical.warnings` |

`sources` 只写**能指到发布方**的条目，不写「网友说」。查不到出处的说法（热度、荣誉、「最」「第一」）一律不进数据。

### 「预算」怎么写（schema 无 budget 字段 + 红线 R1 不写金额）

主理人要求路线含预算信息，但两件事同时成立：**`packages/shared/src/travelbook/types.ts` 里没有预算字段（不能改 schema）**，
且 **R1 与 `roadbook-scan-content.mjs` 禁止票价金额与班次时刻**（`[0-9]+ ?元`、`HH:MM` 一律报错）。
本轮的做法是把预算写成**可自查的构成与档位口径**，不写数字：

- `practical.lodgingNote`：住宿落点 + 档位差异（「县城比景区门口宽松、代价是多开几十公里山路」）；
- `practical.bookingNote`：哪些项目另行收费（门票 / 索道 / 电梯 / 游船 / 观光车 / 讲解分批次）、哪两个时段最贵最挤；
- `pois[].ticketNote`：逐个说明「分别计费 / 预约 / 限流 / 停航封闭」，让读者知道钱花在哪几处；
- `practical.fuelNote`：加油与快充的密度差异、新能源需要回城补能的段落。
若将来确需真实数字，只能走「口径 + 出处 + 日期」三件套（例如引官方公示价并注明核验日期），
在此之前**不要为了显得详实而写估价**。
