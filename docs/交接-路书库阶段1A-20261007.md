## 三、写一条路线的标准流程（照做，可复制给任何 AI）

1. **定规格**：从 PRD §6.1 剩余清单（见本文 §5）取一条，先定 `id / 名称 / provinces / cities / anchorCity / tier / layer / shape / primaryMode / modes / days / editorRank`。
2. **查城市名**：跑 §2 第 ③ 步的命令，逐字照抄。
3. **算里程再动笔**：先定 `totalKm`，再把逐日 `plan[].distanceKm` 分摊到**和等于 totalKm（误差 ≤1km）**，最后把 `segments` 拆分到与 totalKm 偏差 ≤25%。**先算后写，不要写完再改。**
4. **核对道路编号**：
   ```bash
   ls data/roads/index/            # national.json / expressway.json / provincial.json ...
   grep -c '"G321"' data/roads/index/national.json
   ```
   规则：**G+1~2 位 = 高速**（查 `expressway.json`）；**G+3 位 = 普通国道**（查 `national.json`）；**S 开头 = 省道**（查 `provincial.json`）。
   **查不到就绝不硬写** —— 改用 `refPending: true` + 俗称（如「大鹏半岛南西路」），`roadClass` 写「景区公路」/「县道」/「城市道路」。
5. **填内容**：`intro`（overview / bestSeason / days / difficulty / difficultyNote / audience）、`nodes`（≥4）、`segments`（≥3）、`pois`（≥6，其中 `mustSee:true` ≥3）、逐日 `plan`、`practical`（**carFree 必填 ≥20 字**）、`sources`（≥1）。
6. **落盘**：`Write` 一次写 2~4 条（别一次写 7 条，JSON 容易截断）；剩下的用 `Edit` 往 `routes` 数组末尾追加。
7. **立刻自检**：
   ```bash
   node -e "const j=JSON.parse(require('fs').readFileSync('data/presets/roadbooks/<文件>.json','utf8'));
   j.routes.forEach(r=>console.log(r.id, 'days',r.days,'plan',r.plan.length,'intro',r.intro.days,
     'km',r.totalKm,'Σplan',r.plan.reduce((s,d)=>s+d.distanceKm,0),
     'pois',r.pois.length,'must',r.pois.filter(p=>p.mustSee).length,
     'nodes',r.nodes.length,'seg',r.segments.length, r.layer, r.editorRank,
     'carFree',(r.practical.carFree||'').length))"
   ```
8. **跑闸门**：`node scripts/build-roadbook-index.mjs`，**与你文件相关的 error 必须清零**。
9. **报告**：列出没把握的字段、所有 `refPending` 路段、所有 2 位小数近似坐标，交主理人复核。

## 七之三、协作纪律（批次 1B 踩出来的，务必遵守）
