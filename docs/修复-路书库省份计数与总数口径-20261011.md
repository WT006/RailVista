# 修复 · 路书库省份计数与总数口径 · 2026-10-11

## 问题现象

路书库页面（`/roadbook`）存在三处计数不一致：

| 位置 | 显示值 | 期望值 |
|------|--------|--------|
| 右上角 overview 总数 | 147 | 142（仅 published） |
| 左下角「共 N 条」 | 100（被 limit 截断） | 142（全量 published） |
| 省份 chips 角标 | 宁夏/贵州等缺失 | 宁夏3/贵州3/陕西4… |

## 根因分析

### 根因一：API `listTravelRoutes` 的 total 取自截断后数组

```
// 修复前
const filtered = queryTravelRoutes(summaries, q);  // q 含 limit=100，内部已 slice
return { total: filtered.length, ... };             // total = 100
```

`queryTravelRoutes`（`packages/shared/src/travelbook/types.ts:698-700`）在内部执行 `slice(offset, offset + limit)`，返回的已是截断后的 100 条。`listTravelRoutes` 直接用 `filtered.length` 作为 total，导致前端拿到 `total=100` 而非全量 142。

### 根因二：前端 `routeCountByProvince` 从截断后的 routes 本地统计

```
// 修复前
const routeCountByProvince = computed(() => {
  const map = new Map<string, number>();
  for (const r of routes.value) {       // routes.value 只有 100 条
    for (const p of r.provinces) map.set(p, (map.get(p) ?? 0) + 1);
  }
  return map;
});
```

`routes.value` 是被 `limit=100` 截断后的列表。宁夏、贵州等省份的路线排在 100 条之后，所以本地 Map 统计结果中这些省份没有计数，chips 角标缺失。

### 根因三：`getTravelOverview` 的 totalRoutes 含草稿路线

```
// 修复前
totalRoutes: snap.routes.length,    // 147（含 5 条 draft）
```

`queryTravelRoutes` 默认过滤 `r.status === 'published'`（`types.ts:675`），所以 list 返回 142 条。但 `getTravelOverview` 用 `snap.routes.length` 返回全部 147 条（含 5 条 draft），导致右上角 147 与列表 142 不一致。

同理，`counts = summarizeTravel(snap.routes.map(toTravelSummary))` 也基于全量 147 条（含草稿），`counts.routes`、`counts.byProvince`、`counts.byMode` 等均含草稿路线。

## 修复方案

### API 侧（`apps/api/src/services/travelRoutes.ts`）

#### `listTravelRoutes`：拆分分页参数，total 取截断前全量

```typescript
// 修复后
const { limit, offset, ...queryWithoutPaging } = q;
const allFiltered = queryTravelRoutes(summaries, queryWithoutPaging);  // 不含 limit/offset
const total = allFiltered.length;                                       // 142
const start = Math.max(0, offset ?? 0);
const end = limit && limit > 0 ? start + limit : allFiltered.length;
const routes = allFiltered.slice(start, end);                           // 手动截断
const counts: TravelCounts = summarizeTravel(
  summaries.filter((r) => r.status === 'published')                    // counts 也只算 published
);
return { total, routes, counts };
```

关键改动：
1. 从 `q` 中解构出 `limit`/`offset`，剩余查询参数传给 `queryTravelRoutes`，避免内部截断
2. `total` 取截断前的 `allFiltered.length`
3. 手动 `slice(start, end)` 实现分页
4. `counts` 从 `summarizeTravel(summaries)` 改为 `summarizeTravel(summaries.filter(published))`，确保 `counts.routes`/`byProvince`/`byMode` 等均只含 published 路线

#### `getTravelOverview`：totalRoutes/totalPois/counts 只算 published

```typescript
// 修复后
const publishedSummaries = snap.routes.filter((r) => r.status === 'published').map(toTravelSummary);
const counts = summarizeTravel(publishedSummaries);
const published = snap.routes.filter((r) => r.status === 'published');
return {
  totalRoutes: published.length,        // 142
  totalPois: published.reduce(...),    // 1132
  ...
};
```

### 前端侧（`apps/web/src/pages/RoadbookHome.vue`）

#### 新增 `provinceCounts` ref，从服务端全量统计取值

```typescript
const provinceCounts = ref<Record<string, number>>({});

// loadRoutes 中
provinceCounts.value = data.counts?.byProvince ?? {};
```

#### `routeCountByProvince` 优先用服务端全量，回退本地统计

```typescript
const routeCountByProvince = computed(() => {
  if (Object.keys(provinceCounts.value).length) return provinceCounts.value;
  // 回退：仅当服务端未返回 byProvince 时从本地 routes 统计
  const map = new Map<string, number>();
  for (const r of routes.value) {
    for (const p of r.provinces) map.set(p, (map.get(p) ?? 0) + 1);
  }
  return Object.fromEntries(map);
});
```

返回类型从 `Map<string, number>` 改为 `Record<string, number>`（Object），因为模板中 `routeCountByProvince[p.shortName]` 比 `.get()` 更简洁且不需要 Map 方法。

#### 模板从 `.get()` 改为 `[]` 访问

```html
<!-- 修复前 -->
<i v-if="routeCountByProvince.get(p.shortName)" class="rb-chip-n">
  {{ routeCountByProvince.get(p.shortName) }}

<!-- 修复后 -->
<i v-if="routeCountByProvince[p.shortName]" class="rb-chip-n">
  {{ routeCountByProvince[p.shortName] }}
</i>
```
