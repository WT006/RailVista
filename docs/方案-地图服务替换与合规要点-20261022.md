> 版本：v1.4 ｜ 日期：2026-10-22 ｜ 状态：Web 底图已换 MapLibre+天地图；天气署名已落地；脚本侧高德可后置  
> 文件名保留「地图服务…」以免断链；正文已覆盖 **地图 + 天气（和风 / Open-Meteo）**。  
> 关联：`docs/鸿蒙化迁移规划报告.md`、`docs/设计-鸿蒙化改造-20261009.md`、`apps/web/src/map/amap.ts`、`apps/api/src/services/qweather.ts`、`apps/api/src/services/skyMet.ts`  
> 背景：高德上线后需交服务费；天气侧需厘清和风商用与 Open-Meteo 非商用限制；目标为公开上线时控制费用并合规。

## 1. 结论速览

### 1.1 地图

| 端 | 目标底图 | 费用取向 | 说明 |
|---|---|---|---|
| **鸿蒙 App** | 华为 Map Kit（花瓣地图 / `@kit.MapKit`） | 底图基本可按免费使用 | 勿用华为 **JavaScript** API 做网页 |
| **网页 Web** | **天地图**（或 MapLibre + 天地图瓦片） | 官方写明免费开放（有配额） | 与 App 地图 SDK **分开选型** |
| **API 运行时** | 已不依赖高德 / 百度 Web 服务 | — | 驾车兜底：OSRM；地名兜底：Nominatim；几何：本地 / OSM |
| **离线脚本 / 历史数据** | 可暂留高德 | — | 建库用，**不挡公开上线** |

**地图一句话**：App 用华为、Web 用天地图；两端数据仍走自有 BFF，只换「画底图」的引擎。

### 1.2 天气

| 场景 | 建议 | 说明 |
|---|---|---|
| **公开商用 / 有广告或收费** | 优先 **和风**（走现有 BFF） | 可商用；约每月前 5 万次免费；**必须 UI 署名** |
| **仅本地 / 纯非商用试用** | 可继续 **Open-Meteo 免费档** | 免费 API **禁止商用**；须 CC BY 署名 |
| **鸿蒙 App** | **可以用和风**（推荐仍走 BFF） | 无鸿蒙专用 SDK，HTTP API / 服务端转发即可；与 Web 共用 Key |
| **鸿蒙规划备选** | Weather Service Kit + 合规天气源 | 见迁移报告「零费用」路线；Kit 协议需实测，**不能**把免费 Open-Meteo 当商用主源 |

**天气一句话**：公开上线别默认白嫖 Open-Meteo；用和风可以，但要归因、控量、按时付账单；鸿蒙与 Web 共用 BFF 最省事。

## 2. 为何两端分开

华为地图产品页：[华为地图服务 Map Kit](https://developer.huawei.com/consumer/cn/hms/huawei-MapKit)  
官方价目：[HMS 服务价格](https://developer.huawei.com/consumer/cn/hms/price/)

| 场景 | 计费（公开价目摘要，以官网为准） |
|---|---|
| Android / 鸿蒙侧 SDK **地图加载** | 价目表中 Android SDK 地图加载标为**免费**；鸿蒙 NEXT 系统 Map Kit 社区/实操口径多为基础展示当前不按次收加载费；须签协议、标审图号 |
| **JavaScript** 地图加载 | **收费**：约 **¥37.5 / 千次**（0～10 万次/月档），更高档约 ¥30/千次 |
| 路径规划 / POI / 地理编码等 | 按次收费；另有每月约 **¥2398 代金券**可抵（当月有效） |

「¥37.5 / 千次」含义：网页每成功加载一次地图实例通常计 1 次，按每 1000 次收 37.5 元——**不是**每月固定 37.5 元。公开站点流量下成本易快速升高，故 **Web 不采用华为 JS**。

百度 / 高德 / 腾讯等公开**商用**常需商业授权（例如腾讯商业授权公开口径约数万元/年量级），与「控费公开上线」目标不符，不作为 Web 首选。

## 3. 现状：项目里高德用在哪

### 3.1 上线必须处理（运行时 · Web 底图）

| 位置 | 作用 | 约略规模 |
|---|---|---|
| `apps/web/src/map/amap.ts` | 加载高德 JS API 2.0 + 样式 | ~45 行 |
| `AtlasMap.vue` | 全国图：折线、Marker、**聚合、热力**、自定义 InfoWindow | ~2835 行 |
| `TripMap.vue` | 行程图：折线、站/景/车/GPS、卫星层 | ~1929 行 |
| `DriveTripMap.vue` | 自驾图：路线、车辆、卫星、`setFitView` | ~1202 行 |
| `CorridorMap.vue` | 走廊图：折线、站/景、卫星 | ~816 行 |
| `RouteDetail.vue` | 路线详情小地图 | ~770 行 |
| `DriveTrip.vue` | 仅预加载 `loadAmap` | 很轻 |

主要依赖的高德能力：

- 基础：`Map` / `Polyline` / `Marker` / `InfoWindow` / `Pixel` / `setFitView` / `setZoomAndCenter`
- 样式：`mapStyle: amap://styles/grey`（`AMAP_MAP_STYLE`）
- 图层：`TileLayer.Satellite` + `RoadNet`
- 插件（全国图）：`AMap.MarkerCluster`、`AMap.HeatMap`
- 自定义 HTML Marker、`isCustom` InfoWindow

环境变量：`VITE_AMAP_KEY` / `VITE_AMAP_SECURITY`（见 `apps/web`）。

### 3.2 运行时已基本不用高德

- `apps/api/.env.example`：写明 API **不再**调用高德 Web 服务（geocode / 驾车 / 站 POI）。
- `roadRouting.ts`：在线兜底为 **OSRM**（已去掉百度驾车）。
- `roadIndex.ts`：地名兜底为 **Nominatim**（已去掉百度 geocode）。
- `useGeolocation.ts`：浏览器 GPS，与高德无关。

### 3.3 可后置（离线脚本 / 落盘数据）

- `scripts/lib/amap.mjs`：geocode / POI / 驾车（建库、补缝）。
- 一批 `scripts/amap-*.mjs`、`harvest-amap-scenic.mjs`、`fill-road-*.mjs`、`build-place-index.mjs` 等。
- 数据中的 `amap-poi`、`source: amap`、行政区划落盘等——**已写入 JSON，运行时只读**。

公开上线**不必**先换这批脚本；后续补库可评估天地图等。离线 `scripts/baidu-geo.mjs` 仍存在但**运行时已不调用百度**；勿再为生产配置 `BAIDU_MAP_KEY`。

### 3.4 坐标系备注

- 高德：GCJ-02。
- 天地图：CGCS2000（工程上常近似按 WGS-84 叠自有数据）。
- 仓库已有 `packages/shared/src/geo/coordTransform.ts`（GCJ ↔ WGS），前端页面当前几乎未直接调用。  
  **换底图后必须做一次贴合回归**（走廊/景点相对底图的偏移）。

## 4. 天地图能否替换 · 改动规模与难度

### 4.1 能力对照

| 能力 | 天地图 / MapLibre+天地图 | 评价 |
|---|---|---|
| 底图展示 | ✅ | 可替换 |
| 折线 / 点 / 弹窗 | ✅ | API 不同，需重写 |
| 卫星影像 | ✅ | 可替换 |
| 灰阶样式 | ⚠️ | 不如高德丰富，可接受或 MapLibre 自绘 |
| Marker 聚合 | ⚠️ | 全国图痛点，宜 MapLibre + 插件或自研 |
| 热力图 | ⚠️ | 同上 |
| `setFitView` 类便利 API | ⚠️ | 需自算 bounds |
| 脚本侧 geocode/驾车 | ✅ 有，质量/配额不同 | **可后置** |

### 4.2 规模与难度判断

| 维度 | 判断 |
|---|---|
| 范围 | 主要 `apps/web` 地图页；API 几乎不动；脚本可不动 |
| 代码耦合 | **无**统一地图抽象，页面直接 `new AMap.*` |
| 难度 | **中等偏大** |
| 粗估 | 适配层 + 5 页迁移 + 聚合/热力 + 坐标回归 ≈ **1～2 人月**（一人推进） |

推荐实现路径：

1. **MapLibre GL + 天地图瓦片**（聚合/热力/自绘走廊更友好），或纯天地图 JS（与 AMap 更像但高级能力更弱）。
2. 先抽薄适配层，再按易→难迁移：`RouteDetail` → `CorridorMap` → `DriveTripMap` → `TripMap` → `AtlasMap`。
3. **不要**为省钱把 Web 换成华为 JS。

## 5. 公开上线合规与注意事项

免费开放 ≠ 无限制。公开给他人使用时，至少同时满足：

1. **天地图服务 / 版权条款**  
2. **国家地图管理与互联网相关要求**

### 5.1 天地图侧（服务与版权）

参考：[JS API 入门](http://lbs.tianditu.gov.cn/api/js3.0/guide.html)、省级节点条款示例（如[天地图山东服务条款](https://www.sdmap.gov.cn/policy/%E6%9C%8D%E5%8A%A1%E6%9D%A1%E6%AC%BE.html)、[广东版权声明](https://guangdong.tianditu.gov.cn/index/page/copyrightNotice.html)）。以申请 Key 时勾选的**最新全文**为准。

| 事项 | 注意 |
|---|---|
| Key | 必须申请；浏览器端 / 服务端勿混用；建议绑**域名白名单** |
| 配额 | 个人日配额有限；公开流量大需企业开发者或提额 |
| 来源 | 使用内容应**注明来源**（天地图） |
| 权利标识 | **不得删除、遮挡、替换**版权、商标、审图号等 |
| 商标 | 「天地图」标识属国家基础地理信息中心；**产品勿称「天地图」**，勿近似混淆 |
| 禁止 | 批量扒瓦片/反编译、转售地图数据、干扰服务、传播违法内容等 |
| 许可性质 | 使用许可，**非**底图版权转让 |

### 5.2 国家法规侧（登载公开地图）

主要依据（公开文本）：

- 《[地图管理条例](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)》
- 《[地图审核管理规定](https://www.gov.cn/zhengce/2019-08/13/content_5711407.htm)》
- [规范 APP 登载使用地图行为的通知](https://www.gov.cn/zhengce/zhengceku/202405/content_6950568.htm)

要点摘要：

| 主题 | 要点 |
|---|---|
| **送审 / 审图号** | 向社会公开的地图一般应送审并取得审图号，页面（常见左下角）**显著标注**。直接使用带审图号公益性地图且未改国界/行政区划等可免审；**叠加全国铁路/公路/景点后不宜默认免审**，应向主管部门确认。 |
| **有效期 / 备案** | 互联网地图服务审图号常见约 **2 年**有效，到期重审；审核通过后可能需按规**定期备案**新增标注。 |
| **测绘资质** | 向公众提供「地理位置定位、地理信息上传标注、地图数据库开发」等互联网地图服务，应依法取得相应测绘资质。仅底图 + **自有**线路展示，重点多在送审/标注；开放用户随意上传标注则风险升高。 |
| **内容红线** | 不得表示危害主权统一、涉密、破坏民族团结等禁止内容；有用户标注须有审核与处置。 |
| **APP / 网站** | 注明地图来源与审图号；版图完整；网站 **ICP 备案**；涉及位置隐私须明示并征得同意。 |
| **服务器** | 若被认定为互联网地图服务单位，地图相关服务器宜在境内。 |

### 5.3 上线前自查清单（Web + 后续 App）

- [ ] 注册天地图开发者，创建应用，配置 Key 与域名白名单；保存已同意的服务条款版本。  
- [ ] 页面显著标注：来源「国家地理信息公共服务平台天地图」+ **审图号**（以官方/审核结果为准）。  
- [ ] 不遮挡天地图自带 logo / 版权条。  
- [ ] 产品命名与文案不使用「天地图」商标作自有品牌。  
- [ ] 不批量下载、镜像、转售瓦片；不把天地图数据当自有数据售卖。  
- [ ] 向自然资源主管部门确认：叠加走廊/景点是否需**地图审核**及如何标注。  
- [ ] 控制用户标注能力；开放上传则加强审核。  
- [ ] 完成 ICP；隐私政策覆盖 GPS / 位置。  
- [ ] 评估配额是否够公开流量；不够则企业认证 / 提额。

- [ ] 换底图后做坐标贴合回归（GCJ / CGCS2000≈WGS）。

## 6. 建议实施顺序（仍待立项编码）

### 6.1 地图

```
确认合规口径（审图 / 标注）
  → 选定 Web 引擎（推荐 MapLibre + 天地图瓦片）
  → 抽地图适配层 + 环境变量（VITE_TIANDITU_TK 等）
  → 迁移小地图页 → 行程/自驾 → 全国 Atlas（聚合/热力）
  → 去掉生产路径对 VITE_AMAP_* 的依赖
  → 鸿蒙侧按既有规划接 Map Kit（与本文 Web 并行，互不阻塞）
  → 脚本侧高德：公开上线后按需再替换
```

### 6.2 天气（可与地图并行）

```
确认公开是否商用
  → 商用：配置和风 Host+Key，生产 WEATHER_PROVIDER=auto|qweather
  → UI 按实际 source 署名（和风 / Open-Meteo）
  → 鸿蒙：天气走 BFF，不把 Key 打进 App
  → 非商用试用才可长期依赖 Open-Meteo 免费档
  →（可选）鸿蒙再验证 Weather Service Kit，再决定是否下线和风
```

**明确不做（本阶段）**：

- 不为「省钱」把 Web 换成华为 JS。  
- 不把 OSM 裸瓦片当作国内公开站唯一底图（版图 / 审图风险）。  
- 不在未确认审图口径前宣称「已完全合规上线」。  
- **不把 Open-Meteo 免费 API 当作公开商用生产主源。**  
- 不在鸿蒙端硬编码和风 Key。

## 8. 天气服务：现状、协议与项目改动点

### 8.1 Open-Meteo 是什么

开源气象 API（[open-meteo.com](https://open-meteo.com/)）：按经纬度返回预报字段（气温、云量、能见度、降水概率等）。免费档通常**无需 Key**。

本仓库用途：

| 模块 | 路径 | 作用 |
|---|---|---|
| 景点 ETA 天气 | `apps/api/src/services/qweather.ts` | 未配和风或和风失败时回退 Open-Meteo |
| 天象观景气象 | `apps/api/src/services/skyMet.ts` | 事件时刻云量等，走 Open-Meteo |
| 前端展示 | `TripMap.vue` 等 | 调 BFF `/api/weather/spots`，不直连第三方 |

### 8.2 和风 vs Open-Meteo（公开上线）

| 项 | 和风 QWeather | Open-Meteo 免费档 |
|---|---|---|
| 商用 | **允许**（遵守许可） | **不允许**；商用需付费订阅 |
| 费用 | 天气类约每月前 **5 万次免费**，超出按次后付费 | 免费但有日/时限额；商用走 customer API |
| 署名 | 必须标「和风天气/QWeather」+ 链接 | 必须标 *Weather data by Open-Meteo.com*（CC BY） |
| 鸿蒙 | 可用（无专用 SDK；走 BFF 或 HTTP） | 同上，但商用仍受限 |

### 8.3 和风开发者许可 · 要注意的点

全文：[开发者许可协议](https://www.qweather.com/terms/developers-eula)。官网摘要见使用限制 / 注明来源 / 缓存文档。

| 类别 | 要求 |
|---|---|
| **归因** | 展示天气处清晰显示「和风天气」或「QWeather」，链到 https://www.qweather.com；推荐「天气服务由和风天气驱动」。可见、独立放置，勿埋进正文或紧挨广告。 |
| **预警 / AQI** | 若使用，须完整展示接口 `refer.sources`，不得改写。（当前主路径多为逐时预报，一般未触及。） |
| **缓存** | **气象数据可合理短缓存**（你们默认约 1800s，接近逐小时推荐）；**禁止**批量缓存/索引 **GeoAPI** 地理数据。 |
| **请求** | 非 2xx 须处理，勿过量错误重试（可能被视攻击并冻号）。 |
| **付费** | 按量后付费；欠款约超 30 天可冻号追缴。 |
| **产品** | 接入产品须合法合规、公序良俗。 |
| **Key** | 留服务端；勿提交公开仓库、勿打进鸿蒙安装包。 |

### 8.4 鸿蒙 App 能不能用和风

**能。** 官方提供 API + iOS/Android SDK，无鸿蒙专用 SDK，但不妨碍：

1. **推荐**：鸿蒙 → 现有 BFF `/api/weather/*` → 和风（与 Web 共用，Key 不进端）。  
2. 端上直调 HTTP 亦可，但 Key 安全与归因仍要做。  
3. 迁移报告里「Weather Kit 替换和风」是**零费用策略**，不是技术禁用。
