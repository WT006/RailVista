## 1. 背景与本期目标边界

ETA 方案给出了完整五层数学模型（里程轴 → 图定曲线 → 延误场 → 卡尔曼融合 → 置信度输出）和 Phase 0-3 路线图。**本期只交付 Phase 0 核心 + Phase 1 主体 + 扩展接口骨架**，即：

| 本期做 | 本期不做（留接口） |
|---|---|
| 里程轴 `buildMileageAxis`（站投影 + PAVA 单调化 + 端点硬钉）——修掉 P0-1 站序比例 | 卡尔曼融合（Phase 2，`basis` 字段预留） |
| 车型参数表 + 运动学反演（梯形速度曲线） | 延误场 δ(s)（Phase 2，`delayOffsetMs` 过渡参数预留） |
| 图定里程⇄时间曲线 `ScheduleCurve` | `progress.ts` / `getUpcoming` 现有逻辑改造（下一轮单独做） |
| **`computeNodeTimeline()`**：站点+景点+终点 全节点的时间结果（到/停/离 + σ 区间 + 置信度） | TripMap.vue UI 接入（下一轮） |
| 可插拔 enricher 管道 + 昼夜/日出日落内置实现（weather 只留接口） | 12306 正晚点接口、众包标注 |

理由：一条 GLM 指令的可验证边界 ≈ 6~8 个新文件 + 单测；融合与 UI 涉及状态机与真机调试，混入会破坏验收确定性。

### 3.2 统一时间数据结构（timelineTypes.ts）

```ts
/** 单个时刻的估计值——所有节点时间字段的唯一形态 */
export interface TimeEstimate {
  /** 预计时刻，绝对 ISO 8601（始终带 +08:00 时区偏移） */
  iso: string;
  /** 1σ 预估区间半宽（分钟）；展示为 iso ± sigmaMin */
  sigmaMin: number;
  /** σ≤3 高 / ≤10 中 / >10 低 */
  confidence: 'high' | 'mid' | 'low';
  /** timetable=图定原值 interpolated=邻站插值 estimated=运动学曲线估计 */
  source: 'timetable' | 'interpolated' | 'estimated';
  /** 本期恒 'schedule'（传入 delayOffsetMs≠0 时 'calibrated'）；Phase 2 扩展 gps/mixed */
  basis: 'schedule' | 'gps' | 'calibrated' | 'mixed';
}

export type TimelineNodeKind = 'origin' | 'stop' | 'spot' | 'terminus';

export interface TimelineNode {
  /** `stop:${seq}` | `spot:${spotId}` | `end` */
  nodeId: string;
  kind: TimelineNodeKind;
  name: string;
  /** 里程轴坐标（米，单调不减；行程方向） */
  kmM: number;
  /** 距折线垂距（米）；投影质量信号，PAVA 权重用 */
  offTrackM?: number;
  /** 预计到达（origin 的 arrival=出发时刻；spot=过景时刻） */
  arrival: TimeEstimate | null;
  /** 预计离开；景点通过=arrival 同值；terminus 的 departure=null */
  departure: TimeEstimate | null;
  /** 停留秒数 = departure−arrival；景点 0；无时刻站点 null */
  dwellSec: number | null;
  /** dwell 补充：'scheduled'=图定营业停 / 'technical'=技术停车（stopover_time=0） */
  dwellType?: 'scheduled' | 'technical';
  /** 相对 now 是否已通过 */
  passed: boolean;
  /** enricher 附加数据，key=enricher.id（如 extras.daylight / extras.weather） */
  extras: Record<string, unknown>;
}

export interface NodeTimelineResult {
  trainCode: string;
  /** 按 kmM 升序；同里程时 stop 排在 spot 前 */
  nodes: TimelineNode[];
  generatedAt: string;
  /** 全部降级/异常说明（时间倒挂、几何可疑、缺坐标……），前端可直接展示 */
  warnings: string[];
}
```

**输入**：

```ts
export interface NodeTimelineInput {
  stops: Stop[];                 // 行程经停（12306 顺序，seq 单调）
  spots: ScenicSpot[];           // 已由 filterSpotsAlongRailway 算出 progressKm/distKm
  path: RailwayPoint[];
  lengthKm: number;
  departure: Date;               // resolveSchedule().departure（已含用户改点）
  arrival: Date;
  offsetMs: number;              // resolveSchedule().offsetMs
  trainDate: string;             // 'YYYY-MM-DD'，HH:mm 兜底换算用
  now: Date;
  /** 折线几何来源 → σ_geo 分档；缺省 'station'（最差档） */
  geoSource?: 'precise' | 'corridor' | 'local' | 'soft' | 'station';
  /** 旧全局平移校准（CalibrationRecord.offsetMs）；Phase 2 换延误场 */
  delayOffsetMs?: number;
}
```

### 3.3 可插拔扩展接口（用户要求③）

```ts
export interface TimelineContext {

  enrich(nodes: TimelineNode[], ctx: TimelineContext): void | Promise<void>;

/** 默认注册表：Phase 2 的 weatherEnricher / visibilityEnricher 在此追加，业务零改动 */
export const TIMELINE_ENRICHERS: TimelineEnricher[] = [daylightEnricher, weatherEnricher];
```

- **daylightEnricher**（本期实现）：对每个节点按 `arrival.iso + 节点投影点坐标` 计算 NOAA 日出日落，写 `extras.daylight = { isDay, sunriseIso, sunsetIso, phase: 'day'|'astronomicalNight'|'goldenHour'|'blueHour' }`（goldenHour = 日出前/日后 40min 窗口，为后续朝霞晚霞景点推荐打底）。纯函数、无依赖、可单测。
- **weatherEnricher**（本期仅占位）：`extras.weather = { queried: false }` + TODO 注明：按 `node.kmM→投影坐标 + arrival.iso（±30min 窗口）` 请求天气 API，回填 `{ cond, tempC, visKm }`。接口先冻结，避免 Phase 2 改数据结构。

### 3.4 主流程（nodeTimeline.ts → computeNodeTimeline）

```
1  buildMileageAxis(stops, path, lengthKm) → S[m]（§3.5）
2  buildScheduleCurve(S, stopTimes, profile, geoSource) → curve
     逐区间 solveSegment(ΔS,ΔT)：β=(1/a⁺+1/a⁻)/2；判别式 D=ΔT²−4βΔS
     D≥0 → 梯形（小根 v，钳 v_cap）；D<0 → 匀速降级+warning
     哨兵：v>1.4·v_cap 或 ΔT_k≤0 → 匀速+warning；segSlack[k]=max(0,ΔT−T_min)
3  站点节点：arrival/departure 取图定 ISO（source=timetable）；
     缺时刻站 → source=interpolated（按相邻站时间线性插 kmM 对应时刻，σ=站间隔×0.25）
     dwellSec=D−A；stopover_time 可用时标 dwellType（technical：stopover=0）
4  景点节点：定位区间 k → arrival.iso = D_k + τ(s_j−S_k)（source=estimated）
     departure=arrival，dwellSec=0；恰在站上（|s_j−S_k|<150m）→ 用该站图定时刻
5  passed：nowKmM = curve.kmAtTime(now+delayOffsetMs)；node.kmM < nowKmM − 100
6  σ 合成：σ² = σ_plan² + (σ_geo/v_seg/60)²
     σ_plan = σ_0 + γ·√(Δt_h)；interpolated 站再取 max(σ, 0.25×邻站间隔min)
     σ_geo 表：precise/corridor 150m、local 300m、soft 500m、station max(500, 0.12×ΔS_k)
7  enrichers 按 TIMELINE_ENRICHERS 顺序执行（写入 extras）
8  排序合并（stop 先于 spot）→ warnings 汇总 → 返回
```

**单位约定（写死在模块头部注释，GLM 最易犯错处）**：内部一律 **米(m)/毫秒(ms)/米每秒(m/s)/米每秒²(m/s²)**；`progressKm×1000` 进，`TimeEstimate.iso` 与 `sigmaMin`（分钟）出；`TRAIN_PROFILES.vCapKmh` 存 km/h，`resolveTrainProfile` 内部转 m/s。

### 3.5 里程轴（mileage.ts，Phase 0 核心修复）

```ts
export function buildMileageAxis(params: {
  stops: Stop[]; path: RailwayPoint[]; lengthKm: number;
}): { kmM: number[]; offTrackM: number[]; warnings: string[] }
```

1. 首末站硬钉 `0 / L`；中间有坐标站 `projectToRailway().progress × L`；
2. 无坐标站：按相邻有坐标站的**图定时间比例**插值里程（时间插值比线性插值准）；
3. PAVA 保序回归（权重 `1/(offTrackM+200)`）——复线/枢纽投影乱序的根治；
4. 零长区间保护：`ΔS<200m` 强制拉开并等比压缩后续；
5. 端点重钉 `S_0=0, S_m=L`。
