## 一、数据文件结构（一个字都不要改）

路径：`data/presets/roadbooks/segments-<省>-<n>.json`

```jsonc
{
  "version": "1",               // 数据文件自身的代际标记（库内 32 个文件用 "1"、23 个用 "0.9.0"，不参与校验）
  "updated": "2026-10-22",
  "area": "省份（补强覆盖：本轮前库内 N 条，本文件 +M —— 主题1 / 主题2 / 主题3）",
  "note": "本文件含 M 条路线：路线名1（M 日 / editorRank X）、路线名2（…）。<里程口径一句话>。<坐标口径一句话>。",
  "routes": [ /* 路线对象数组 */ ]
}
```

- `note` 必须**逐字**列出本文件每条路线的 `name`（或 `id`）。自检脚本会查。
- `area` 里**不要写「首次覆盖」**。本轮目标省库里早有路线，写「首次」就是伪 claim。
  格式照抄：`「省份」（补强覆盖：本轮前库内 N 条，本文件 +M —— 主题1 / 主题2 / 主题3）」`。
  「本轮前库内 N 条」用 `scripts/roadbook-coverage.mjs --prov=省` 查到的 `routes` 数。
- `version` 字段：写 `"1"`（库内 32 个文件用 "1"、23 个用 "0.9.0"，该字段不参与任何校验，全库一致即可）。

## 二、路线对象 schema

权威定义在 `packages/shared/src/travelbook/types.ts`（`TravelRouteDetail`）。字段清单：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全库唯一，kebab-case 英文 |
| `name` | ✅ | 中文路线名，与顶层 `note` 逐字一致 |
| `subtitle` | ✅ | 一句亮点 |
| `alias` | | 关键词别名数组 |
| `provinces` | ✅ | **省级简称**数组（如 `["陕西"]`），必须与 `_regions.json` 的 `shortName` 一致 |
| `cities` | ✅ | **地级行政区全称**数组，必须在 `_regions.json` 的 `cities[].name` 里逐字命中 |
| `anchorCity` | ✅ | 主入口城市，必须在 `cities` 里，且在 `_regions.json` 命中 |
| `modes` | ✅ | 玩法数组；**必须包含 `selfdrive`**（徒步/岛屿类例外见红线 V8） |
| `primaryMode` | ✅ | 必须是 `modes` 的子集 |
| `shape` | ✅ | `loop` / `point` / `outback` / `corridor` |
| `tier` | ✅ | `national` / `regional` / `city`，**必须与 layer 匹配**（见 §三） |
| `layer` | ✅ | `L1`~`L5`，**必须显式写**（V15） |
| `tags` | ✅ | 4~7 个中文标签 |
| `summary` | ✅ | 一句话速写 |
| `totalKm` | ✅ | 总里程，**必须等于 `Σplan[].distanceKm`**（容差 1km） |
| `mileageNote` | ✅ | 里程口径说明（见 §五） |
| `days` | ✅ | 天数，**必须等于 `plan.length` 且等于 `intro.days`** |
| `bestSeason` | ✅ | 月份数组 |
| `difficulty` | ✅ | 1~5 |
| `roadRefs` | ✅ | 全线主要道路编号 |
| `startNode` / `endNode` | ✅ | 必须在 `nodes[].name` 里 |
| `intro` | ✅ | 见下 |
| `nodes` | ✅ | ≥4 个，见下 |
| `segments` | ✅ | ≥3 段，见下 |
| `pois` | ✅ | ≥6 个，≥3 个 `mustSee`，见下 |
| `plan` | ✅ | 逐日行程，长度 = `days` |
| `practical` | ✅ | 见 §七 |
| `sources` | ✅ | ≥1 条，见 §八 |
| `editorRank` | ✅ | 全库唯一，落在层区间内 |
| `status` | ✅ | `"published"` |
| `updatedAt` | ✅ | `"2026-10-22"` |

### intro
```jsonc
"intro": {
  "overview": "整体介绍正文（200~400 字，按 §六的语气）",
  "bestSeason": "文字版最佳季节（说明为什么）",
  "seasonNotes": [ { "months": [7,8], "note": "该时段的特殊说明" } ],  // 可选，2~3 条
  "days": 4,                    // === days
  "daysNote": "可压缩/可延展说明",
  "difficulty": 2,
  "difficultyNote": "难度成因（海拔？路况？步行？停车？）",
  "audience": ["适合人群 1", "适合人群 2", "适合人群 3"],
  "avoid": ["不建议人群 1", "不建议人群 2"]      // 可选
}
```

### nodes（≥4）
```jsonc
{ "name":"节点名", "province":"陕西", "city":"西安", "lng":108.94, "lat":34.34,
  "role":"start|end|hub|stay|pass", "note":"这个节点在路线里承担什么（40~80字）" }
// elevM 只在有把握时写，否则**省略**
```

### segments（≥3）
```jsonc
{ "id":"xx-s1", "index":1, "name":"从 → 到", "fromNode":"节点名", "toNode":"节点名",
  "via":["途经地名1","途经地名2"],
  "roadRefs":["G5","G108"],          // 国道在前
  "roadClass":"国道",                  // 只有 8 个合法值，见下
  "distanceKm":194, "driveHours":2.8,
  "condition":"路况描述", "note":"该段特殊提示",
  "poiIds":["xx-p-1"], "toll":true }
```

**`roadClass` 只能取这 8 个值**（写别的直接 ERROR）：
`国道` `高速` `省道` `县道` `乡道` `景区公路` `城市道路` `步道`

> `roadClass` 是**行政等级**，不是用途/环境描述。写「边防公路」「林区道路」「山区公路」→ ERROR。
> 环境描述放 `note` / `via`。

**道路编号纪律**：
- `G`+1~2 位 = 高速（在 `data/roads/index/expressway.json`）
- `G`+3 位 = 国道（在 `data/roads/index/national.json`）
- `S`+1~3 位 = 省道（在 `data/roads/index/provincial.json`）
- 查证：`node scripts/roadbook-lookup.mjs check <编号>`（子命令 `poi/place/roads/check/cities/rank`）
- **不在册就绝对不要编编号**。改写俗称 + `"refPending": true`。
- ⚠️ `S`/`X` 编号跨省同名（`S30` 在册但挂的是别省的路线名）。涉及省道县道的段，
  **优先改写成该段实算日志里给出的国道/高速编号**，否则用 `refPending: true` + 俗称。
- 第一个 `roadRefs` 元素如果不是 `^[GSXYC]\d+$` 形式，必须置 `refPending: true`，
  除非 `roadClass` 是 `景区公路`/`步道`/`乡道`。

### pois（≥6，≥3 个 mustSee）
```jsonc
{ "id":"xx-p-1", "name":"景点名（从已核验库逐字复制）", "province":"陕西", "city":"西安",
  "category":"mountain|water|landform|grassland|forest|desert|village|temple|ruin|culture|cityview|roadside|food",
  "lng":109.28, "lat":34.38,
  "tagline":"一句话核心特色",
  "intro":"景点介绍正文（80~200 字，写清楚「是什么 + 为什么值得去 + 有什么可看」）",
  "mustSee":true, "visitHours":3,
  "bestTime":"最佳时段与理由",
  "ticketNote":"门票/预约提示（见红线 R1）",
  "level":"国家 5A 级旅游景区",      // 可选；只写库里能查到的等级
  "detourKm":3 }
```
- `category` **必填**，缺了直接阻断全库校验。
- `ticketNote` **必填**，每条 POI 都要写。
- POI 合法字段集就上面这些，**不要塞多余 key**（曾经混进过 `"type": null`）。

### plan（长度 = days）
```jsonc
{ "day":1, "title":"当天主题", "fromNode":"节点名", "toNode":"节点名",
  "distanceKm":180, "driveHours":2.8,
  "roadRefs":["G5"], "stayCity":"住宿城市（必须在 cities 里）",
  "poiIds":["xx-p-1"],
  "summary":"当天行程正文（≥60 字）",
  "tips":["提示1","提示2"] }        // ≥2 条
```

## 三、layer / tier / 天数 / 里程 对应表

| layer | 含义 | tier | 天数 | 单日里程上限 | editorRank 区间 |
|---|---|---|---|---|---|
| L1 | 国家级大环线 | `national` | 1~15 | 300km | 1~99 |
| L2 | 区域级省域环线 | `regional` | 3~7 | 300km | 100~199 |
| L3 | 景区几日游 | `city` | 2~5 | 250km | 200~299 |
| L4 | 周末周边 | `city` | 1~3 | 150km | 300~399 |
| L5 | 小众目的地 | `city` 或 `regional` | 2~5 | 250km | 400~499 |

- **L4 必须同时含 `selfdrive` 与 `public` 两种玩法**（V16）。
- `tier` 与 `layer` 不匹配 → ERROR。
- `editorRank` 必须是**全库唯一**且落在本层区间（V11 + 判据 G）。**号段按批次连续追加，不要回填空档**。

## 五、坐标与里程：怎么取、怎么写

### 坐标
**唯一合法来源是仓库内已核验的 POI 库**，用这个脚本查：

```bash
node scripts/roadbook-poi.mjs 陕西 兵马俑 华山 太白山 袁家村
node scripts/roadbook-poi.mjs --prov=甘肃 --list=石林
```

数据源：`data/roads/roadside-spots.json`（36893 条，含 tier / 评分 / 开放时间 / 亮点 / 资质）
+ `data/presets/scenic-spots.json`（811 条）+ `data/roads/places-admin.json`（3564 个行政中心）。

- 查不到 → **不写坐标**，该景点只出现在 `pois[].name` / `tagline` / `intro` 与 `segment.via` 里，
  或者干脆不作为独立 POI。
- **专名逐字复制**。曾经把库里的「省嵬城遗址」写成「塞嵬城」——靠扫描与人工复核才发现。
- 景区等级只写库里带出的 `4A/5A/国家森林公园/全国重点文物保护单位`；
  拿不着的写「以官方公告为准」。
- 「老子生地」「庄子故里」这类归属争议**并列表述，不下定论**。

### 里程
用本地国家公路网拓扑做 A* 最短路实算：

```bash
# 输入：[{ "id":"book-id", "legs":[{ "key":"s1", "from":"西安", "to":"铜川",
#        "a":[108.94,34.34], "b":[108.98,34.34], "note":"说明" }]}]
pnpm roadbook:measure tmp/m-x.json tmp/m-x-out.json
```

输出每段：`km` / `min` / `straightKm`（直线上界）/ `ratio`（实测÷直线）/ `engine`（`direct` = 本地无解）/ `roads`（命中道路编号）。

**取值规则**：
- `ratio ≤ 1.6` → **直接采用实测值**；
- `ratio > 1.6` 或 `engine=direct` → 改按**直线 × 1.3~1.35** 推算。

**`mileageNote` 必须逐段交代**（采用值、被弃用的实算值、对应比值），格式照抄库内既有文件：

> 「5 天累加 828km：成都—江油 194km、……。实算段（本地国家公路网拓扑最短路，国道+高速+省道主干）：
> 成都→绵阳 131.2km（直线 115km，比值 1.14），均在阈值内直接采用。推算段：剑门关→翠云廊取 10km
> （实算 20.4km、与直线之比 2.60，本地主干网绕行虚高、弃用，按直线 8km 乘 1.3）。」

**里程一致性（硬判据）**：
- `Σplan[].distanceKm` **必须等于** `totalKm`（容差 ≤1km）。
- `Σsegment[].distanceKm` 允许偏离 `totalKm` ≤25%；差的那部分写进 `mileageNote`
  （通常是「城内短驳」这类不成段的量，只进 plan 不建段）。
- 段内节点往返（如 `阆中 ↔ 苍溪`）允许，用来表达「以营地为轴的当日往返」。

## 六、文案风格与长度

| 字段 | 长度要求 | 写法要求 |
|---|---|---|
| `intro.overview` | 200~400 字 | 按「主题分段推进」写，不要写成景点清单。讲清楚「为什么这条线值得走」 |
| `plan[].summary` | **≥60 字** | 写当天怎么走、看什么、节奏怎么安排，带具体地名 |
| `plan[].tips` | ≥2 条 | 实用提醒：停车、排队、时段、装备 |
| `practical.lodgingNote` | 60~90 字（硬上限 120） | 住哪一片 + 为什么这么住。**不写具体酒店名，不写金额** |
| `practical.foodNote` | 60~90 字（硬上限 120） | 当地特色菜写具体菜名 + 用餐时段。**不写金额** |
| `practical.carFree` | **≥20 字** | 必须含四要素：「高铁/机场抵达 → 市内接驳 → 景区专线 → 结论」 |
| `practical.fuelNote` | 40~80 字 | 加油与快充密度差异、新能源需要回城补能的段落 |
| `practical.signalNote` | 30~60 字 | 信号与通讯覆盖 |
| `practical.gearNote` | 30~60 字 | 装备建议 |
| `practical.bookingNote` | 50~90 字 | 哪些项目另行收费、哪两个时段最贵最挤、预约规则 |
| `practical.warnings` | ≥3 条 | 风险提示：汛期、封山、检查站、高原反应、限流 |
| `pois[].intro` | 80~200 字 | 「是什么 + 为什么值得去 + 有什么可看」 |
| `pois[].ticketNote` | 30~80 字 | 门票/预约/限流/停航封闭。**不写金额** |
| `nodes[].note` | 40~80 字 | 这个节点在路线里承担什么 |
| `segments[].condition` | 30~60 字 | 路况描述 |
| `segments[].note` | 20~50 字 | 该段特殊提示 |

**语气**：像一本写得好的自驾手册，克制、具体、可执行。不吹不黑，不写「震撼」「绝美」「必打卡」
这类营销词，不堆形容词。每条 POI 至少一个具体事实（构造、年代、地质、族群、吃什么）。

**「预算」怎么写**（schema 没有 budget 字段，且 R1 禁止写金额）：
写成**可自查的构成与档位口径**，不写数字：
- `practical.lodgingNote` → 住宿落点 + 档位差异（「县城比景区门口宽松，代价是多开几十公里山路」）
- `practical.bookingNote` → 哪些项目另行收费（门票 / 索道 / 电梯 / 游船 / 观光车 / 讲解分批次）、哪两个时段最贵最挤
- `pois[].ticketNote` → 逐个说明「分别计费 / 预约 / 限流 / 停航封闭」，让读者知道钱花在哪几处
- `practical.fuelNote` → 加油与快充密度差异

## 七、内容三渠道怎么落到字段里

| 渠道 | 用来定什么 | 写在哪 |
|---|---|---|
| OTA（携程/飞猪/同程/去哪儿）成熟跟团/自由行线 | 天数结构、停留顺序、住宿落点、是否值得单列一地 | `sources[].usedFor` = 「X 日结构与景区换乘、住宿落点顺序」 |
| 小红书与各类自媒体攻略 | 美食具体到菜名、排队与限流体验、拍摄时段、避坑 | `practical.foodNote` / `bookingNote` / `plan[].tips` |
| 文旅公众号与官网、文物与水利部门公告 | 等级与名录、预约与限流规则、汛期与封山公告 | `pois[].ticketNote` / `intro.seasonNotes` / `practical.warnings` |

**`sources` 只写能指到发布方的条目**，不写「网友说」。查不到出处的说法（热度、荣誉、「最」「第一」）一律不进数据。

```jsonc
"sources": [
  { "title":"携程《西安—华山—渭南》跟团线路行程安排", "publisher":"携程旅行", "url":"https://…",
    "usedFor":"3 日结构与景区换乘、住宿落点顺序" },
  { "title":"华阴市文旅局华山景区开放与索道公告", "publisher":"华阴市文化和旅游局", "url":"https://…",
    "usedFor":"开放时间与索道运营时段" }
]
```

**不确定的条目**：在对应字段里写「以官方公告为准」，并在最终汇报里单独列出来。
**不要为了显得详实而编数字。**

## 八、踩过的坑（这些真的会扣分）

1. **大段 JSON 用 Edit 工具改会截断** → 整条路线写成 `tmp/route-x.json`，再用 Python/Node
   `json.load` / `json.dump(..., ensure_ascii=False, indent=2)` 合并进目标文件；
   合并时做「同 id 覆盖、不同 id 追加」，重复执行不会产生双份路线。
2. **英文与拼音漏字只有扫描器能抓到**（`Multi` / `Also` / `FILM` / `widened` / `roadside` / `竹HIGH`）。
   → 每次改完必跑 `node scripts/roadbook-scan-garbage.mjs <文件>`；
   带 `assert` 的批量替换脚本会静默中断后续替换，**改完必须回读磁盘**。
3. **繁体字扫描器抓不到**。批次里出现过「低洼街**區**」这类繁简混用。
   → 每批交付前补跑一次：`node -e "const t=require('fs').readFileSync(process.argv[1],'utf8');const m=t.match(/[區臺裏後於時觀覽橋門龍飛國學會體點與從來還開關無處業產當經進]/g);console.log(m?[...new Set(m)]:'无繁体')" <文件>`
4. **顶层 `note` 里的路线条数会静默变错** → `note` 用脚本生成，不要手打。
5. **`category` 缺失会直接阻断全库校验**（判据 D）。
6. **城市名口径**：民族自治州必须全称；`plan[].stayCity` / `nodes[].city` / `pois[].city` 都要落在 `cities` 里；
   `anchorCity` 要么在 `cities` 里、要么能在 `_regions.json` 的 name/alias 命中。
7. **`S`/`X` 编号跨省同名**（见 §二）。
8. **别把景点名「顺手改得更顺」**。
