## 1. 报告目的与结论速览

本报告用于把 **RailVista（万里路书）** 从一个 Vue 3 + Hono BFF 的 Web 应用，完整迁移为 **HarmonyOS 原生应用（ArkTS + ArkUI）**，并对 API 调度、鸿蒙特色能力、语言选择、工程量、开发工具、AI 辅助、上架合规等做一次系统性规划。

**一句话结论**：保留服务端 BFF（零费用数据源不变），端侧用 ArkTS + ArkUI 重写 UI 并接入花瓣地图 / 天气 / 分享 / 定位等鸿蒙系统 Kit，核心计算引擎从现有 TypeScript 分层复用到 ArkTS，全量功能一次对齐，个人开发者身份上架，工程量约 **104 人天、52 个任务、M0–M4 五个里程碑**。

## 3. 鸿蒙官方能力调研结论（来自华为开发者联盟知识库）

### 3.1 语言生态 —— 仓颉到底是什么

用户关心的「仓颉」调查结果：

- **仓颉（Cangjie）** 是华为自研的**静态类型**编程语言，主打**高性能、强安全、跨平台、智能化**。
- **ArkTS** 是 HarmonyOS 应用开发的**主力语言**（TS 超集 + ArkUI 声明式），主打**易学、生态丰富、极简开发**。
- 鸿蒙是**多语言生态**：ArkTS + 仓颉 + C/C++ 三者可**跨语言互操作**，C/C++ 模块可封装为 ArkTS/仓颉模块供上层高效调用。

**本项目的结论**：主体用 **ArkTS**；仓颉作为**可选热点优化项**，首版**不引入**。理由：现有 `packages/shared` 是纯 TypeScript，迁到 ArkTS 成本最低；性能关键路径（行程进度/卡尔曼融合/坐标转换）先用 ArkTS 实现，若真机压测出现瓶颈，再用仓颉或 C/C++ 封装这少数几个模块。

### 3.2 地图 —— 花瓣地图

- 入口：`@kit.MapKit`（`petalMaps` / `mapCommon`），提供地图显示、交互、绘制、检索、导航、LBS。
- 需在 AGC 签署「华为地图服务使用协议」；标准地图审图号 **GS(2024)1955**。
- **注意**：个人开发者账号能否签署该协议，需在 AGC 实测验证（列为前置验证任务 V-2）。

### 3.3 天气 —— Weather Service Kit

- 入口：`@kit.WeatherServiceKit`（`weatherService`），依经纬度返回格点天气（实况/逐时/逐日，含 AQI、紫外线、能见度）。
- 依赖 `Location Kit` 提供经纬度；免费系统能力，不产生 API 费用。
- 仍需在 AGC 验证个人开发者可签性与数据项覆盖（前置验证 V-1）；服务端保留 Open-Meteo 免费兜底。

### 3.4 分享与特色能力（可调用能力清单）

| 能力 | Kit | 应用场景 |
|---|---|---|
| 系统分享面板 | Share Kit | 纪念票 / 路书分享 |
| 碰一碰 / 隔空传送 | Share Kit | 行程/票面跨设备直达 |
| 跨设备直达 | App Linking Kit | 分享链接唤醒页面（列增强项） |
| 定位 | Location Kit | GPS 混合定位、行程进度、地理围栏 |
| 实况窗 | Live View | 行程进度 / 下一站常驻提醒（列增强项） |
| 意图框架 | Intents Kit | 小艺建议 / 位置感知推荐（增强项） |
| 车机流转 | Car Kit | 导航信息流转车机（远期） |
| AR 导航 | AREngine Kit | AR 导航（远期） |

### 3.5 UI / 动效 / 图标 / 色彩字体规范

- **动效**：ArkTS 属性动画 + 显式动画 `animateTo`；图标用 `SymbolGlyph`/`SymbolSpan`（`SymbolEffectStrategy.SCALE` 整体缩放 / `HIERARCHICAL` 分层动效）。
- **材质**：系统材质 `Material`（沉浸光感）。
- **色彩/字体**：优先用系统资源 `$r('sys.color.*')`、`$r('sys.font.*')`，遵循华为鸿蒙设计规范。

## 6. 关键技术方案

### 6.1 端侧工程结构

- 新建 `apps/harmony/`（DevEco Studio 标准工程：`Entry` 主模块 + `feature`/`har` 功能模块）。
- 不进 pnpm 根 scripts，鸿蒙用 DevEco + hvigor 独立构建运行。
- 目标基线 **API 12+**（HarmonyOS NEXT）。

### 6.2 TS → ArkTS 复用方案（核心结论）

**采用「分层复用」，否决「直接编译 .ets」**。原因（实测自官方 TS→ArkTS 适配规则）：ArkTS 禁止 `any/unknown`、解构、structural typing、index signature、条件/映射/索引访问类型、`as const` 与字面量类型；shared 现有代码含模板字面量类型和不满足规则的写法，**无法零改动编译**。

三类模块分法：

| 类别 | 内容 | 复用方式 |
|---|---|---|
| A 纯算法 | coordTransform / fusion / kinematics / solar / sky / ticket 模型 / roadSign | 手动移植 ArkTS |
| B 领域类型 | types.ts / travelbook types | 脚本自动降级生成 |
| C 需重写 | version.ts 等 | 重写 |

**一致性保障**：`sync-shared-to-harmony.mjs --check` 结构指纹 + fixtures 单测，防 Web/鸿蒙双端漂移（对齐决策 9）。

### 6.3 数据源迁移与降级矩阵

| 数据源 | 正常路径 | 降级路径 | 费用 |
|---|---|---|---|
| 地图 | 花瓣地图 MapKit | 跳转系统地图 App | 0 |
| 天气 | Weather Service Kit | Open-Meteo（服务端） | 0 |
| 铁路 | 12306（BFF） | 本地兜底 presets | 0 |
| 航班 | FlyClaw（BFF） | aviation.ts 本地库兜底 | 0 |
| 铁路几何 | OSM Overpass（BFF） | localRails 本地图 | 0 |
| 景点 POI | 现有离线库 `data/` | — | 0 |
| 驾车规划 | 本地路网 A* + 花瓣地图 POI 锚点 | — | 0 |
