# 价格与时间计算链

> 用户原话诉求：看准价格、回程返程合理计算时间、中转也要看价且预留合理中转时间。
> 这一节就是那三件事的落地规程。

## 1. 机票

### 去程回程必须分别查
只查去程是新手第一大坑。**去程、回程分别查询**，各自独立给出时刻与价格。

### 中转方案
- 支持中转，且**必须给出中转方案的预留时间**
- 预留规则：
  - 国内联程 **≥1.5h**
  - 跨境 **≥2h**
  - 同城市需换航站楼 **按 3h 起**
- 低于阈值时，结果里必须显式标注："中转时间偏紧，前段延误导致误机需自行承担"
- 中转方案的价格优势要和中转的时间成本、误机风险**一起呈现**，不许只报低价

### 多源比价
- RailVista `/api/flights/search`（源：飞猪 FlyClaw）为底价源
- 联网检索补充其他公开渠道可见价
- **所有价格必须标注 `source` 与 `as-of`（查询时间）**
- 学生票资格在结果里提示，但**不替用户认证**

### 红眼/早班的连锁影响（必写）
- 红眼航班：标注"凌晨抵达，首日只能算半天/需额外订前一晚住宿"
- 早班机：标注"需凌晨 X 点出发前往机场，市区交通是否已停运"

### 回程时间算法（核心）
以最晚返程日为界**倒推**：

```
最晚返程日
  └─ 回程班次时刻
       └─ 减去 前往机场/车站的市区交通时间
            └─ 减去 安检/取票/候车时间（机场 1.5—2h、高铁 0.5—1h、节假日再加）
                 └─ = 最后一整天必须结束的时刻
```

- ⛔ 不许推荐"最后一晚住景区、第二天早上赶 6 点车"这种方案**而不警告**
- 若用户行程这样排，必须显式写出风险与备选（前一晚回市区住 / 改晚一班）

## 2. 火车

- 12306 by-code 查询
- **预售期约 15 天**，超期返回 `NOT_FOUND` 属**预期行为，不是故障**
- 超期时的正确处理：
  1. 给出"季节参考运价"（标注为参考值，非实时）
  2. 给出**抢票提醒**，并把放票时间点写进出发前清单
- 高铁 ≤4h 通常优于飞机（按门到门总耗时算），**要说出为什么**

## 3. 性价比口径：门到门总耗时

不只看票价，必须算**门到门总耗时**：

```
门到门耗时 = 市区→出发站/机场 + 候车/安检 + 在途 + 到站→市区
```

同时考虑班次密度、正点率口碑。给结论时说出来龙去脉，不许只给"建议坐高铁"。

## 4. 当地小交通

各地差异极大，**必须联网核实当时当地的实际运营情况**并附官方页面链接：

- 景区直通车（贵州类）
- 船班（舟山类：班次 + 天气停航风险）
- 租电动车（桂林类）
- 顺风车/拼车（川西类）

⛔ 不许写死成"一般有""通常有"——这类话在攻略里等于没说。

## 5. 门票

输出格式：

```
门市价 / 预约价 / 优惠票种 + 预约入口 + 放票规则
```

- 价格一律标查询时间
- 查不到写 `unknown`，**不填 0、不写"正常开放"**

## 6. 内容红线（贯穿全部报价）

| 项    | 规矩                                    |
| ---- | ------------------------------------- |
| 票价   | 只陈述，不代买；不承诺"就是这个价"                    |
| 时刻   | 只给量级与班次，不给承诺（"大约 2 小时"而非"保证 2 小时到"）   |
| 里程   | 必须标"估算口径"（公路网 A* 路径里程 ≠ 实际驾驶里程，也 ≠ 直线） |
