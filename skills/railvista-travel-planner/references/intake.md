# 需求识别：先问对人，再谈目的地

## 核心原则

> 用户说"周末去哪"时，**不要立刻抛目的地**。
> 同一个"周末"，一个人说和一家三代说，正确答案是两回事。

## 入口识别

只要上下文是"安排一次出行"，就应触发本 Skill，包括这些模糊表达：

- "十一想出去玩"
- "下周末有两天假"
- "随便推荐个地方"
- "预算 2000 能去哪"

显式说"初始化 RailVista 旅行规划"时进入欢迎与需求识别；
用户已经给出具体旅行任务时**直接沿用，不重复问卷**。

## 问卷纪律

1. **每轮 3—5 问，不一次全抛**——一口气 15 问会把人问跑
2. **硬约束先问，偏好后问**——先确定"能不能去"，再谈"想去哪"
3. **第三轮按需追问**——由前两轮结果触发，不普适全问
4. **选项要能回答，不要开放题**：问"能接受 4 小时以上车程吗"比问"你喜欢什么强度"好答
5. **不索要隐私**：只要出发城市，不要住址；只要人数构成，不要姓名证件

## 第三轮触发规则

| 前两轮结果           | 触发追问                     |
| --------------- | ------------------------ |
| 带老人            | 日均步行强度上限、午休需求、就医便利性      |
| 带儿童            | 年龄段、是否需推车/安全座椅           |
| 固定日期（不可挪）      | 是否接受"临近按天气微调"            |
| 预算紧张           | 可否接受夜班火车 / 红眼航班 / 青旅     |

## 收敛

拿到硬约束后先做**可行性过滤**（时间够不够、预算够不够、身体条件允不允许），
过滤完再进入候选推荐。宁可因为"3 天去西藏太赶"劝退，也不要给出注定翻车的方案。
