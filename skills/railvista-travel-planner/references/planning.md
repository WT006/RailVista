# 模式二 · 确定目的地后的逐日编排

保留 bys-travel-plan 的 S3—S9 阶段机（调研 → 对齐 → 规划 → 核查 → 交付 → 修改恢复），
在此基础上增补六个模块。

## 增补模块

### 1. 出行方式对比（每次必出）
跟团游 / 拼车 / 包车 / 自由行，四类并列对比：

| 方式   | 价格    | 自由度 | 适合谁     | 主要风险      |
| ---- | ----- | --- | ------- | --------- |
| 跟团游  | 低     | 低   | 预算敏感/长辈 | 购物点、节奏被动  |
| 拼车   | 中     | 中   | 2—4 人   | 拼友随机、时间妥协 |
| 包车   | 高     | 高   | 家庭/多人   | 成本、司机资质   |
| 自由行  | 视规划而定 | 最高  | 有经验者    | 全程自理、容错低  |

### 2. 旅行问题智库（老玩家的坑）
针对具体目的地输出真实会踩的坑：存包、偏远地区交通（顺风车/大巴/直通车）、
抢票提醒、高反与就近医院、雨季/封山/停航窗口。

### 3. 体验项目库
可预订体验项（滑雪 / 飞拉达 / 潜水 / 雪山俱乐部等），
**只给当时当地真实可订的，不写"一般都有"**。

### 4. 小确幸层（住宿与观景）
- 观景房 / 日照金山 / 星空房：给具体朝向与季节时段，**不承诺一定看得到**
- 住宿区选择：讲清"住哪个区"的理由（交通/餐饮/安静度）

### 5. 可编辑生成页
产出必须可编辑、可回退版本。Markdown、HTML、图片卡**来自同一份行程数据快照**。

### 6. 出发前清单
- 证件、票务（含抢票放票时间点）
- 预约（景区/餐厅/体验项，含放票规则）
- 天气窗口与备选方案
- 就近医院（尤其高原、带老人儿童）

## 逐日行程的必备字段

每天必须输出：

```
日期 / 城市 / 住宿区
当日交通（含实测或估算时长，标口径）
站点与停留时长
餐饮落点
可玩时间合计
当日风险与备选（天气/人流/体力）
```

⛔ 不写"上午逛逛、下午自由活动"这种空洞排期。
