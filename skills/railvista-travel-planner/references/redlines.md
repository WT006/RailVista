# 红线与署名

## 三大底线（继承 bys-travel-plan，违反即方案作废）

### 1. 不为完整而编造数据
票价、开放时间、路程时长查不到就写 **"未知"**：
- 不写 `0`
- 不写 "正常开放"
- 不用"大概""差不多"糊过去

### 2. 不为精确而增加注册门槛
- 不要求用户注册地图 / 天气 / 酒店 API
- 优先用宿主已有工具 → 再联网检索 → 最后才保守估算，且**估算必须标注**

### 3. 不为好看牺牲事实一致性
Markdown、HTML、图片卡、对话里的版本，**必须来自同一份行程数据**。
改一处必须同步全部，禁止对话里说 A、文档里写 B。

## RailVista 附加内容红线

| 项    | 规矩                                        |
| ---- | ----------------------------------------- |
| 票价   | 只陈述，不代买；不承诺"就是这个价"                        |
| 时刻   | 只给量级与班次，不给承诺                              |
| 里程   | 必须标"估算口径"（A* 路径里程 ≠ 实际驾驶里程，也 ≠ 直线距离）      |
| 住宿   | 给区域与理由，不给具体房型库存承诺                          |
| 观景   | 日照金山/星空只给季节时段与概率，**不承诺一定看得到**             |
| 医疗   | 高反/就近医院信息作提示，**不构成医疗建议**                  |
| 订票   | ⛔ 不订票、不支付、不预约、不改签，只给入口与规则                 |
