---

## 1. 背景与问题

现有项目面向单趟列车 **Z8991（西宁→拉萨）**，提供：

- 真实铁路线与站点、沿途风景点地图展示
- GPS + 时刻表混合定位
- 自定义发车时间、站点校准、「即将到达」提示

用户希望升级为更通用的产品 **RailVista**：支持按出发站 / 到达站 / 日期选择列车，展示该行程站点与沿途风景，并保留车上实时定位能力；风景内容后续用 AI 自动发现，并支持用户编辑。

---

## 2. 产品定位

**一句话：**  
RailVista 是铁路旅客的 **车上沿途风景与行程定位伴侣**；同时支持出行前预览线路与风景。

**价值优先级：**

1. **核心（A）：** 上车打开 → 知道现在大概在哪 → 下一处风景 / 下一站是什么  
2. **兼得（B）：** 出行前选车次 → 预览全程地图与风景列表  

**目标用户（MVP）：** 正在车上的旅客（优先）；出行前规划者为次要场景。

**发布形态：** 可演示的 MVP 优先；暂不做商业化、账号体系。

---

## 3. 目标与非目标

### 3.1 目标（MVP）

- 用户可通过 **出发站、到达站、日期** 查询直达车次并进入行程地图
- 支持 **OD 区间截取**（进度、站点、风景仅针对用户乘坐区间）
- 地图展示经停站；支持点击查看站点详情
- 保留并泛化现有能力：自定义发车偏移、站点校准、GPS+时刻表混合定位、「即将到达」、图层开关
- 未上车也可预览全图与风景列表（有数据时）
- 同时适配 **手机与电脑** 浏览器
- 至少保留一条可演示的精品线路内容（如 Z8991 风景与站点体验）

### 3.2 非目标（MVP 明确不做）

- 购票、余票展示（不作为主功能）
- 用户账号 / 登录 / 云端同步
- 中转换乘方案
- AI 自动搜索 / 一键生成沿途风景（**第二版**）
- 全国任意车次 **OSM 真实钢轨折线** 自动生成（**第二版**；MVP 用站点折线示意）
- 严格的性能 / 弱网 SLA 指标（本版 PRD 暂不约定）

## 4. 版本范围

### 4.1 MVP（v1）— Must

| ID | 能力 | 说明 |
|----|------|------|
| M1 | 选站与日期查车次 | 出发站、到达站、日期 → 调用商用时刻表 API → 展示直达车次列表 |
| M2 | 进入车上地图 | 用户选择具体车次后进入行程地图主界面 |
| M3 | OD 截取 | 仅计算与展示用户选择的出发站→到达站区间内的站点、行程进度、风景 |
| M4 | 自定义发车时间偏移 | 沿用现有逻辑：整体平移时刻，本地持久化 |
| M5 | 站点校准 | 沿用现有逻辑：到站后校准后续 ETA / 进度 |
| M6 | 经停站标记与详情 | 地图标记；点击查看站名、到发时刻、简介（有则展示） |
| M7 | GPS + 时刻表混合定位 | 有可用 GPS 时与时刻表融合；否则回退时刻表 |
| M8 | 「即将到达」 | 优先下一风景；否则下一站 / 终点逻辑（沿用并泛化） |
| M9 | 图层开关 | 铁路（示意线）、经停站、风景、列车估算位置、手机 GPS |
| M10 | 风景点展示 | 地图标点 + 详情（简介、建议观景时段、左右侧窗等字段；有数据则展示） |
| M11 | 出行前预览 | 未开启实时定位时也可浏览全图与风景 / 站点列表 |
| M12 | 响应式布局 | 手机与电脑均可使用（同一 Web 应用） |

**MVP 风景数据策略：** 不做 AI 生成。采用 **预置演示数据**（至少 Z8991）+ 后续版本的手工 / AI 能力；无风景的车次允许列表为空，但不阻塞定位与站点功能。

**MVP 铁路线形策略：** 使用 **经停站依次连线的示意折线** 作为铁路层与定位投影基准；界面需可区分「示意线」（文案可在实现时定）。

### 4.2 第二版（v2）— Later

| ID | 能力 | 说明 |
|----|------|------|
| L1 | OSM 真实铁路线 | 能解析到路径则用真实轨道折线 + GPS 投影；失败则降级站点折线并提示 |
| L2 | AI 一键生成沿途风景 | 选车次 / 进入行程后一键生成并在地图标点 |
| L3 | AI 点位质量 | 尽量吸附到铁路线附近；带建议观景时段、车窗左右侧 |
| L4 | 风景本地 CRUD | 用户新增 / 修改 / 删除风景点；MVP 阶段约定存 localStorage，v2 落地 |
| L5 | 重新生成与覆盖确认 | AI 再次生成前确认是否覆盖已有点 |
| L6 | 收藏车次 / 行程 | 方便再次进入 |

### 4.3 工程边界（持续）

- 只做 **直达车次**，不做中转
- 不做购票闭环
- MVP 不做账号；v2 若上云再议

## 5. 用户故事与主流程

### 5.1 核心故事（车上）

1. 乘客打开 RailVista，选择出发站、到达站、乘车日期。  
2. 系统展示直达车次列表；乘客选择自己的车次（及实际上下车站，若与车次始发终到不同则作为 OD 截取）。  
3. 进入地图：看到区间内站点、示意铁路线、（若有）风景点、当前估算位置。  
4. 乘客可修正发车时间；到某站后可校准站点。  
5. 底部持续展示当前位置摘要与「即将到达」的风景或车站。  
6. 乘客可开关图层、点击站点 / 风景查看详情。

### 5.2 次要故事（出行前）

1. 用户按同样方式选 OD、日期、车次。  
2. 不依赖 GPS，预览区间地图、站点与风景列表，用于了解沿途可看什么。

### 5.3 主流程示意

```text
[选出发站 / 到达站 / 日期]
        ↓
[商用 API：直达车次列表]
        ↓
[选车次 + 确认 OD 区间]
        ↓
[加载经停时刻 → 生成站点折线 → 加载预置风景(若有)]
        ↓
[地图主界面：定位 / 校准 / 图层 / 即将到达]
```

## 6. 功能需求详述

### 6.1 车次查询

- 输入：出发站、到达站、日期  
- 输出：直达车次列表（车次号、出发/到达时刻、历时、出发/到达站名等，以所选 API 字段为准）  
- 供应商：需求层只约定 **商用时刻表 API**；具体厂商（如聚合数据等）实现阶段再定  
- 异常：无结果、API 失败时给出明确失败提示，允许重试

### 6.2 OD 截取

- 用户选择的出发站、到达站可以是该车次经停序列中的任意前后站（须出发站在到达站之前）  
- 行程进度 0%–100% 对应该截取区间，而非整趟车始发终到（除非 OD 即为始发终到）  
- 站点列表、风景过滤、即将到达、里程文案均限定在该区间

### 6.3 地图与定位

- **站点：** 标记区间内经停站；点击展示详情（站名、到发时刻、简介等）  
- **示意铁路：** 按区间站点顺序连线  
- **列车位置：** 由时刻表在区间进度上插值；有合格 GPS 时与时刻表融合（沿用现网融合策略并可参数化）  
- **发车偏移 / 站点校准：** 行为与现 Z8991 产品一致，存储 key 需按车次 + OD 维度区分，避免串数据  
- **即将到达：** 基于当前时间与进度，优先下一风景点，否则下一站或终点  
- **图层：** 铁路 / 经停站 / 风景 / 列车估算 / 手机 GPS，状态可本地记住

### 6.4 风景（MVP）

- 展示字段（有则显示）：名称、地图坐标、简介、建议观景时段、左右侧窗等  
- 数据来源：预置数据包（按车次或线路关联）；无数据时地图无风景层点、列表为空，功能其余可用  
- 地图必须能标出风景位置（有数据时）

### 6.5 风景（v2，摘要）

- AI 根据车次经停与线路上下文自动生成候选风景并标图  
- 点位尽量靠近铁路线；含观景时段与左右侧建议  
- 用户可本地增删改；重新生成需确认覆盖  
- 标点需可区分「AI 生成」与「用户编辑」（实现时定交互）

### 6.6 多端

- 同一套 Web：手机优先可用，桌面端布局可读、可操作（地图与侧栏 / 底栏自适应）

## 7. 数据与集成（逻辑模型）

### 7.1 外部依赖

| 依赖 | 用途 | 版本 |
|------|------|------|
| 商用列车时刻表 API | 站到站车次、经停与时刻（以实现时供应商能力为准） | MVP |
| 地图 SDK（现高德） | 底图、标记、定位展示 | MVP |
| OpenStreetMap | 真实轨道折线构建 | v2 |
| LLM / 搜索类 AI | 沿途风景自动发现 | v2 |

### 7.2 核心实体（逻辑）

- **Station：** 站名、站码、经纬度（坐标可来自预置库或地理编码，实现阶段定）、到发时刻  
- **TrainTrip：** 车次号、日期、全程经停序列  
- **UserSegment：** 用户 OD 截取后的子行程（进度基准）  
- **RailwayPolyline：** 折线点列（MVP 由站点生成；v2 可为 OSM）  
- **ScenicSpot：** 名称、坐标、简介、时间窗、左右侧、来源（预置 / AI / 用户）、所属车次或线路键  
- **UserPrefs：** 发车偏移、校准信息、图层开关（本地存储；key 含车次与 OD）

### 7.3 本地存储（MVP）

- 偏移、校准、图层等继续使用浏览器本地存储  
- v2 风景 CRUD 亦先以 localStorage 为默认方案（本 PRD 已锁定）

## 8. 与现有 z8991-map 的关系

| 现有能力 | 迁移策略 |
|----------|----------|
| 时刻偏移 / 校准 / GPS 融合 / 即将到达 / 图层 | 抽象为与车次无关的引擎，数据由「当前行程」注入 |
| Z8991 站点与 18 处风景 | 作为 RailVista 预置演示行程保留 |
| OSM 青藏铁路折线构建脚本 | 保留为 v2「精品线 / 真实折线」资产与参考实现 |
| 页面文案中的 Z8991 硬编码 | 改为通用品牌 RailVista + 动态车次 / OD |

## 9. 验收标准（MVP）

1. 任选两站与日期（API 有数据时）可列出直达车次并进入地图。  
2. 选择非始发/非终到的中间站作为 OD 时，进度与站点 / 风景仅反映该区间。  
3. 关闭 GPS 时仅靠时刻表仍能显示估算位置与即将到达；开启 GPS 后模式标识有变化（与现产品一致的可感知行为）。  
4. 可修改发车时间、可做站点校准，刷新后仍保留（同一行程维度下）。  
5. Z8991 演示数据下，风景点在地图可见，点击可见详情字段。  
6. 无风景数据的车次：站点与定位仍可用，不出现阻断性错误。  
7. 手机与桌面视口下，主流程可完成（选车 → 看图 → 看详情 / 即将到达）。  
8. 不出现购票、登录、中转相关入口（MVP）。
